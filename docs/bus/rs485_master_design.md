# 串口实时主站 · 完整设计方案（RS-485/串口后端，形态 B 线程1）

> 状态：v1.0（2026-09-24 立稿，讨论中）。第一个消费者：**R1-7A 七轴臂**（宇树 IM 系电机，
> 协议内芯 `unitree_im`）。依据：厂商协议 PDF + IM6014 C++ demo 源码逐行核实 +
> timesync v1.9 的 USB 串口延迟实测。与 `socketcan_master_design.md` /
> `ethercat_master_design.md` 平行，共享 master.hpp 五要素与形态 B 线程模型。

## 0. 总判断

串口总线的一切特点来自"它是最古老最简单的那个"：UART 无帧概念、无仲裁、无总线时钟。
由此三条设计公理：

1. **确定性来源 = 我们的轮询表**（比 CAN 更彻底——CAN 还有仲裁最坏上界，串口连这个都没有，
   主站说几时发就几时发）；
2. **1kHz 的真瓶颈在主机侧不在线上**——6M 波特下 7 节点全扫线时间仅 ~537µs，
   USB 串口适配器未调优的 RX 攒批（FTDI 默认 16ms）才是杀手；
3. **lock-step 轮询在 USB 串口上撑不起 1kHz**——每事务等响应 = 每事务吃 1-4ms USB 往返。
   唯一正解是**帧泵**：命令流出去、反馈流回来、按 ID 自配对、命令年龄恒定 1-2 拍。
   厂商 demo 自己就是纯流式写的（异步线程只 write，读线程找帧头），帧泵是被背书的模型。

**通用性总纲**：骨架只认字节和时间，协议只是小内芯，机器只是配置。
判据：骨架代码 grep 不到任何协议词汇（零类型泄漏的反向版）。

## 1. 分层与通用性（写一次 × 每族一类 × 每台一份配置）

| 层 | 变化频率 | 内容 |
|---|---|---|
| 机器 | 每台臂 | 关节→总线ID 映射、每关节减速比、限位、kp/kd 机型资产 —— 纯 yaml/URDF |
| 协议内芯 | 每族协议 ~400 行 | 帧布局/CRC/定点换算/状态映射/特殊命令 —— 一个 C++ 类，不做配置驱动 |
| 485 骨架 | 写一次 | transport/framer/pump/scheduler/health 五件套 —— 协议零词汇 |

骨架五件套：

- **transport**：`IoTransport` 接口（read/write/close，全部非阻塞语义）。
  实现① `TermiosTransport`（全部 Linux 坑封死在这）；实现② `FakeTransport`（进程内假从站，零硬件全链测试）。
- **framer**：`FrameSpec` 参数化的字节流→帧提取（见 §4）。
- **pump**：RT 帧泵线程（本设计的核心，见 §3）。
- **scheduler**：节点表×时间片编排——全扫/分组交错/guard/超时/广播插队，不知道帧里是什么。
- **health**：per-node 陈旧检测 → 语义状态 + 遥测计数器（见 §8）。

协议内芯接口（unitree_im 是第一个实现）：

```
encode(cmd, ratio) → bytes          # 纯函数, ratio 是入参不是常量 (厂商 demo 硬编码 38/3 的教训)
decode(bytes, ratio) → feedback     # 纯函数
framespec() → FrameSpec
capabilities() → 位图               # HAS_HW_WATCHDOG / HAS_BROADCAST / FIXED_LEN / ...
map_state(raw) → 中立词汇            # READY/ENABLED/QUICK_STOP/FAULT
special(cmd)                        # clear/reset/广播等协议特有操作
```

**能力声明防最小公分母**：有无硬件看门狗/广播/定长，骨架按位适配不假设——
有硬件看门狗就管理其 timeout 位，没有就软件看门狗+广播停兜底。

反模式三不：不做 XML/JSON 万能协议描述（每协议一个普通类，可进 gdb）；
ratio/关节名不进代码；协议词汇不越过内芯边界（向上只见 RobotFeedback/RobotCommand）。

第二个消费者已在路上：宇树 UniArmL1（6 轴开源臂，同协议族）——分层此刻成立正好
（两处以上消费才上收）。

## 2. 主机侧（Linux，全部经验来自 timesync v1.9 实测）

**设备形态与适配器能力账**：

| 形态 | 6M 可行性 | 备注 |
|---|---|---|
| USB 串口 FTDI FT232H/FT2232H | ✅（12M 上限） | latency_timer 必调（§2.1） |
| USB 串口 FT232R / CP210x / CH340 / CDC | ❌（≤3M 或 1-2M） | 排除 |
| 原生 UART / PCIe 串口卡 | 视卡规格 | 无 USB 路径，确定性最好；TIOCSRS485 原生换向 |
| 宇树配套 USB 转 485 模块 | 待实测 | 芯片型号到货确认（FTDI 系则按 §2.1 调优） |

**termios 清单**：raw 模式（cfmakeraw）、8N1 无流控、**BOTHER 任意波特**（termios2/TCSETS2，
6M 不在标准 B 常量表里）、VMIN=0/VTIME=0（非阻塞读）、TIOCEXCL 独占（防双主站）、
`/dev/serial/by-id/` 固定名 + udev 权限。

**§2.1 latency 自调**：FTDI 系 RX 攒批默认 16ms——短帧永远填不满缓冲、每拍吃满定时器。
探测到 FTDI（sysfs idVendor）即写 `latency_timer=1`，进开机脚本（与 rt_tune_boot 同类）。

**延迟解剖表**（timesync 实测口径）：

| 环节 | 延迟 |
|---|---|
| USB 串口 RX 缓冲（FTDI 调 1 / CDC 类天然） | ~0.5-2ms |
| 未调 FTDI | 16ms（rtt 中位 ~16ms 且散布宽 = 没生效的签名） |
| USB 调度量子（高速 USB 微帧） | 125µs 粒度 |
| 6M 线时间（20B+26B 事务） | 77µs |

**回显检测**：部分自动换向适配器把自发字节回环进 RX。上机第一步空总线自发自收验证；
unitree_im 恰好命令帧头 `FE EE` / 反馈帧头 `FC EE` 首字节不同——framer 层天然可辨，不做丢弃计数。

## 3. 节拍架构（帧泵 = 形态 B 线程1）

落位：**FIFO 90、核2**（RT 布局"核1=CM、核2=总线"的兑现），周期 = 总线 update_rate。

每拍循环（全部非阻塞、缓冲预分配、RT 纪律零 malloc）：

```
拍开始 (clock_nanosleep 绝对节拍)
 ① cmd = cmd_ex.take_latest()          ← CM 的命令 (SpLatest, 取最新)
 ② tx = 调度器给本拍的节点子集 × codec.encode(cmd[j], ratio[j])   (+插队广播帧)
 ③ transport.write(tx_batch)           ← 一次 write, 非阻塞
 ④ drain: while ((n = transport.read(buf)) > 0) framer.push(buf)  ← 排干已到字节
 ⑤ framer 吐出完整帧 × codec.decode → state[j] (转子→输出端换算) → health 更新
 ⑥ state_ex.publish(快照)             ← SpLatest, CM 侧取最新
 ⑦ 遥测计数器/rtt 更新; 超时未响应的节点记一笔
拍结束 (预算: 两个 syscall + 7 帧编解码 ≈ 几十 µs, 1kHz 余量巨大)
```

- **命令年龄恒定 1-2 拍**：本拍消费的是上一/上两拍的响应——与敲门级联语义一致，
  SpLatest 取最新天然吸收；不做"等这一拍的响应"。
- **调度策略**（R1-7A 裁决见 §7）：
  - 全扫：每拍轮询全部 7 节点（总线占用 80%+，无重试余量）；
  - 分组交错：拍 i 轮 J1-J4、拍 i+1 轮 J5-J7（总线占用减半，每节点更新率 = bus_hz/2）；
  - 广播帧插队：急停/全体 stop 不排队，下一拍立即发（ID15 无返回，不占响应窗）。
- **换向 guard**：TX 批次发完后到开收之间的静默时间可配（适配器换向速度实测后定）。
- **响应超时**：节点级（N 拍无反馈记陈旧），不是事务级——帧泵不等单次响应。
- **落后追帧纪律**（2026-09-24 bench_dual_pump 实测发现）：逾期超一个时隙即**跳到未来
  期限，绝不补发**——SCHED_FIFO 同优先级不时间片轮转，补发过期期限 = 无睡眠狂奔 =
  饿死同核兄弟（双泵场景）；跳帧计数入遥测（健康签名 = 0）。

## 4. Framer（FrameSpec 参数化）

```
FrameSpec {
  header            # {0xFC, 0xEE}
  长度模式          # 定长(26B) | 长度域(offset+size+endian) | 静默间隔(Modbus 类)
  crc               # 算法(CRC32-MPEG2/CRC16/sum8) + 位置 + 覆盖范围
}
```

- 定长覆盖 unitree_im；长度域覆盖 Dynamixel 类；静默间隔覆盖 Modbus RTU 类（帧间隙判帧，
  间隔计时由帧泵的拍内时间戳提供）。
- 坏帧处理：CRC 失败或长度异常 → **向前扫描下一个帧头重同步**（丢 1 帧不丢同步）。
- 残缺帧：字节不够一帧 → 留在缓冲等下拍（跨拍拼接是常态，USB 攒批决定的）。

## 5. 协议内芯 unitree_im（实例）

帧格式（PDF+demo 逐行核实，此处只留判读用的最小集）：

- 命令 20B：`FE EE` + 模式字节(id4b+status3b+timeout1b) + res + tor/spd(int16) + pos(int32)
  + kp/kd(int16) + CRC32-MPEG2(含帧头16B)。**MIT 混控原生**（前馈+位置+速度+kp+kd 一帧全带）。
- 反馈 26B：`FC EE`(不入CRC) + 模式字节(自带id) + 双温度 + 电压(2LSB=1V) + 扭矩/速度/位置 +
  MError(u32位码) + 警告(3b) + CRC32(20B)。
- 定点换算（**转子端**）：2560=1Nm、64/2π=1rad/s、32768/2π=1rad、12800/1(Nm/rad)、51200/1(Nm·s/rad)。
- 特殊：clear 故障 = mode6 + tor_raw=-256 魔数；reset = mode7；ID15 广播无返回；
  **timeout 位 1=开启，超 1s 无指令固件自动停机**（恢复须先发 stop 模式清除）。

**状态词汇映射**（中立词汇的教科书案例）：

| 协议态 | 中立词汇 | 触发 |
|---|---|---|
| mode=0 停机 | READY | 上电/使能前 |
| mode=1 FOC | ENABLED | |
| timeout 位回读=1 | QUICK_STOP | 1s 无指令触发（需 stop 清除） |
| MError ≠ 0 | FAULT | 位码触发自动停机 |

**命令翻译器**（ros2_control 接口 ↔ MIT，对全部 MIT 系电机通用）：

| 上层命令 | 翻译 |
|---|---|
| position (CSP) | pos_des=cmd, kp/kd=**yaml 机型资产**, spd=0, tau=0 |
| effort | tau=cmd, kp=kd=0, pos/spd=0（零力矩漂移风险由上层管） |
| MIT 直通 | 五元组原样（RL/VLA ingress 的主场） |

position 档 = "位置模式的 MIT 实现"，与 mujoco 链 kp 位置执行器**完全同构**——kp 调参/
稳态下垂账（τ_g/kp）经验直接迁移，piper mujoco 的两轮调参方法论照抄。

**ratio 参数化**：R1-7A 三款电机三种减速比（J1/J2=6010@32、J3-J5=6014@38:3、J6/J7=5010@16），
从机器 yaml 注入 codec；输出↔转子换算：力矩×ratio、速度/位置÷ratio、kp/kd×ratio²。

## 6. 安全链（终点在电机固件，纵深在我们）

1. **固件看门狗 = 安全终点**（timeout 位每帧开启）：总线断/进程死 → 1s 内自动停机——
   README"驱动器看门狗为安全终点"立场成立。崩溃语义同 EtherCAT：进程死 → 帧停 → 看门狗跳。
2. **使能即锁定**（点火顺序关键）：mode 0→1 切 FOC 后到首条命令之间输出零力矩，
   重力下掉臂（厂商 demo 的 enable 就是这么写的，反例）。我们的 on_activate 序列：
   先读当前位姿 → 随使能发 pos_des=实测位姿 + kp——使能瞬间即锁定，无零力矩窗口。
3. **广播急停**：ID15 stop 一帧全体停机，quick_stop 原子旗每拍直查（同形态 B 急停旁路）。
4. **write() 防线同型照抄**（sim_control 预演的形态）：NaN 门→限位 clamp→步长饱和 + 故障计数器。
5. **看门狗链**：非RT 被 CM 盯（StaleWatch）、CM 被帧泵盯（cmd 陈旧→广播停）、
   帧泵被链路兜底（1s 固件看门狗）——整链无无人监视的生产者。
6. **恢复路径**：MError/超时后 = 停机态；恢复 = clear 魔数帧 → 确认状态回 READY → 使能即锁定重入。
   清故障前先停机（协议要求）。**过流/过热类不自动恢复**（自动 clear 可能复撞——碰撞过流
   清了再使能就是再撞一次），须人工确认后重 arm。
7. **反馈盲区冻结**（2026-09-24 咨询定稿）：命令链活着、反馈链死了 = 开眼发闭眼控。
   单节点反馈 stale 超 N 拍（500Hz 下建议 10 拍=20ms）→ 该节点命令冻结在保持位
   （kp/kd 锁定不需要 host 反馈，冻结是安全的）；过半节点 stale → 广播停。
8. **使能序列回滚**：逐节点确认式使能，任一节点失败 → **回滚全体到 stop**——
   半使能（3 个 FOC 4 个停机）= 腕部垂头，不是可接受稳态。

## 7. 周期账与 update_rate 定案（R1-7A 实例，2026-09-24 厂商口径对账后收口）

### 7.1 时隙预算（最坏情况账）

```
时隙/节点 = 命令帧 33µs + 固件响应 X + 反馈帧 43µs + 换向 guard ~20µs = 96µs + X
7 节点全扫 = 7 × (96 + X)
```

半双工硬约束：**逐节点时隙调度，帧间等待是物理必需**——连发 = 响应撞下一帧
（固件即时应答则撞你后续帧；固件等空闲则 7 个响应同刻互撞，两种死法）。
等待由泵线程绝对节拍执行且**盲发**（不等响应到达）：host 见到响应时线上事件已过去
1-2ms，按见到的响应调度 = 按 USB 速度调度（7×2ms=14ms/扫，废）；盲发让总线跑线速度，
USB 延迟降级为"反馈晚到 1-2 拍"的无害事实。**单帧单 write**（帧独立 URB，绝不合并——
USB 会把两帧拼进同一传输 → 线上背靠背 → 碰撞）。唯一免等帧 = ID15 广播（无返回，
但同值发全体，只用于全体停机/急停）。

| 固件响应 X | 7 节点扫一轮 | 判定 |
|---|---|---|
| 20µs | 0.81ms | 1kHz 可行（19% 余量） |
| 50µs | 1.02ms | 1kHz 压线零余量 |
| **~108µs（厂商上限反推）** | **1.43ms** | **官方上限 700Hz 的构成** |

**官方口径（2026-09-24 到货前沟通）：rate 默认 50Hz、当前机械臂最高 700Hz**——
反推 X≈108µs，与我们保守假设 100µs 收敛（两个独立来源同一数字，账定案）。
物理下限 7×76µs=532µs（6M+帧长决定）——想更快只有提波特率/拆双总线/换协议三条协议外出路。

### 7.2 端到端最坏延迟（500Hz 档）

```
反馈年龄 = 43µs(上线) + ≤1ms(适配器攒批, latency=1) + ≤0.125ms(USB调度)
         + ~0.1ms(tty/read) + ≤2ms(等CM下一拍)  ≈ 3.3ms 最坏 (典型 1-1.5ms)
命令年龄 = ≤2ms(等泵拍) + ≤0.2ms(USB下行)      ≈ 2.2ms 最坏
环路最坏 (命令→执行→反馈回CM) ≈ 5.5ms, 典型 2-3ms
```

"保证"机制 = 预算纪律 + 违规可见：时隙预算制（实测分布后收紧到 P99.999+余量）、
**响应超时跳过**（丢一帧是统计、连丢 N 拍才升级——帧泵永不等待单帧）、
**预算违规计数器**（最坏界被打破的第一现场告警）、CRC 错暴涨 = 时隙碰撞的签名
（处置：放宽时隙一档看计数器归零）。

### 7.3 update_rate 定案

| 档 | 判定 |
|---|---|
| 1kHz 全扫 | **官方判死**（上限 700） |
| 700Hz | 理论天花板≠设计点（零余量），不取 |
| **500Hz 全扫（定案起步档）** | 天花板 71%、余量 29%，与三链/测试资产同频 |
| 1kHz 分组交错（每关节 500Hz） | 物理可行（4节点×204µs=816µs<1ms），留作未来 CM-1kHz 场景，不为此设计 |

厂商默认 rate=50Hz（我们目标的 1/10）——500Hz 是需认真对待的工程档位。
点火采用 **rate 阶梯**（50→100→250→500，每级计数器全零才升级——厂商"爬升"语义的借鉴）。

收发线程：**单线程帧泵**（形态 B 线程1 本义）——RX 无实时性（USB 延迟已 1-2ms，
早读晚读无差）、read 非阻塞永不卡节拍、framer 状态单线程免锁；时隙等待用
`poll(fd, timeout=剩余时隙)` 一石二鸟（睡时隙 + 字节早到早读，发包以绝对期限为准）。
拆 RX 线程仅在实测发现驱动阻塞时考虑（RX 线程 SCHED_OTHER + SPSC 交接，锁不进 RT）。

## 8. 遥测与故障分类

**帧泵计数器**（day1 起，照 write 层故障计数器先例）：CRC 错（按节点）/ 帧头错 /
长度异常 / **响应缺失会计**（按 motor_id 对账：发 7 期待 7——电机拒收坏命令也是静默，
一个会计覆盖双向完整性）/ 广播计数 / rtt 分布（中位+尾部）/ 预算违规 / 换向 guard 违例。
**内核计数器**：`ioctl(TIOCGICOUNT)` 的 parity/frame/overrun/break——frame 涨=线上问题
（端接/EMI），overrun 涨=主机读太慢（软问题），一个 ioctl 切开"线的问题还是我的问题"。
**电机遥测**：双温度/电压/MError/MWarning 逐帧随反馈到 → RobotFeedback 遥测槽 →
supervisor 告警线（温度阈值 + 降额策略 / 电压跌落=电源选型第一手证据）。

**错误面全景（2026-09-24 咨询补全；串口无协议原生错误面，全部自造）**：

| 类 | 错误 | 检测/处置 | 层 |
|---|---|---|---|
| 主机 | **USB 自动挂起**（内核省电睡掉串口） | udev/power_control 禁 autosuspend——开机脚本，**不设必踩** | 部署 |
| 主机 | USB 设备消失（拔线/hub 复位） | read/write 错误 → 语义 FAULT + **禁止运行期自动重连**（回来可能是别的 tty，控制环里盲目重开=危险），人工重 arm | 运行 |
| 主机 | **部分写**（write 返回 < 请求） | 返回值检查，补写剩余——半个命令帧上线=必坏帧 | 代码 |
| 主机 | 波特率/设备配错 | 开机自检 fail-fast：N 拍有效帧率过阈值否则拒启（framer 找不到帧头=0 有效帧是签名） | bring-up |
| 电机 | **自发重启**（brownout/固件崩，回来是停机态） | 反馈 mode 位 ≠ 预期 → 告警 + 重 arm；真机发生过的事 | 运行 |
| 电机 | **位置跳变**（重启丢偏置/多圈异常） | 每拍 \|Δq\| > 物理上限 → 冻结 + FAULT（等价仿真链 F4 状态跳变断言）——静默跳变=机械冲击 | 运行 |
| 电机 | 过温/电压跌落 | 双温度/vol 字段白送的遥测 → 阈值告警 + 降额（连续跑 demo 必遇） | 运行 |
| 电机 | ID 冲突（两电机同 ID） | 上机 ID 扫描逐个验证"恰响应一次"——扫描的验收条件，非可选 | bring-up |
| 调度 | 使能序列半途失败 | 回滚全体 stop（§6.8） | 运行 |

压测→rtt 分布）沿用 2026-09-24 已定稿的排障文档（对话入档，随本设计入库附录）。

## 10. 真机点火顺序（§5.6 四步的串口版，未绿不许跳）

1. **盲读**：上电停机态只发查询/收反馈（不使能），验证 ID 扫描、帧完整率、rtt 分布、TIOCGICOUNT 四计数为零
2. **零速锁定**：使能即锁定序列（§6.2），kp 从小档起步，观测位置保持/温度
3. **微动**：单关节 ±1° 阶跃，验证方向/极性/减速比换算（**ratio 配错的签名 = 动作幅度差 32/12.67/16 倍**）
4. **跟流**：500Hz 全扫跑 JS ruckig 平滑流，对账误差/延迟/温度，绿后收编 verify_robot --chain real

## 11. 验收指标

- 帧：CRC 错 ≤ 0（真机 10 万拍静止+运动各一轮，TIOCGICOUNT 同口径零增长）
- rtt：中位 < 2ms（调好 latency_timer 后），尾部 P99 < 5ms
- 稳态：position 档锁定后位置误差 = τ_g/kp 账内（kp 调参方法论照 mujoco 先例）
- 安全：拔线实验 1s 内自停（固件看门狗实证）；kill 主站进程同口径
- RT：帧泵 WCET p99 < 100µs（核2 隔离），rt_chain_bench 对比无回归

## 12. 实施顺序（先证据后代码，同 CAN/EC）

1. codec 纯函数 + golden frames（零硬件，协议 PDF/demo 双源对拍）

4. 真机到货：上机清单（§8）→ rtt/从机响应实测 → 修订 §7 账与 guard 参数
