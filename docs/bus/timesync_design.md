# MCU↔主机 时间同步 · 简明设计（两帧协议）

> 状态：v1.9（2026-09-11，部署定为 USB 转串口：FTDI 调优条款 + rtt 健康核对入验收）。
> 范围：主机当"时间服务器"，MCU 落 sync.csv 锚点表——**本协议的交付物就是这张表**；
> 采集数据怎么记录怎么落盘归采集侧，不在本文档范围（对它的唯一约束见 §5）。
> 原则：**够用即可**——精度 20ms、单机单会话，不追求完善；接受清单见 §10。

## 1. 目标与预算

| 项 | 值 |
|---|---|
| 对齐目标 | 主机墙钟（CLOCK_REALTIME） |
| 精度要求 | **≤ 20 ms** |
| 同步间隔 | 5 s |
| 链路 | 串口 115200，8N1，无流控（主机侧接法见下） |

**主机侧接法**（按优先级）：**原生 UART**（Orin/RK3576 板载）最佳；
**USB 转串口（CDC-ACM/CP210x/CH340 类）** 天然 1~2ms 缓冲，免调直接用；
**FTDI 类**（FT232 等）默认攒批 16ms，必须先调 `latency_timer=1` 才能用——
命令（拔插后失效，udev 规则固化或主机程序启动时执行一次）：

```bash
echo 1 | sudo tee /sys/bus/usb-serial/drivers/ftdi_sio/ttyUSB0/latency_timer
```

原理：FTDI 收到 UART 字节后攒到缓冲半满或定时器到期才上 USB，6 字节的 REQ 永远填不满
缓冲 → 默认 16ms 每帧吃满；调到 1ms 后残余 0~1ms。生效与否看 §9 的 rtt 核对。

**会话期间主机停用 NTP 跳变校时**（`sudo systemctl stop chronyd` 或等价，事后恢复）——
step 跳变会让 offset 出现阶跃、被插值无声抹平到 5s 的数据上。

## 2. 数据流

```
MCU                                主机
 |--- TIME_REQ (seq) --------------->|   T2 = 收到完整 REQ 后取
 |<-- TIME_RESP (seq, T2, T3) -------|   T3 = 发出 RESP 前取
 | T1 = 发 REQ 前本地取(不上线)      |
 | T4 = 收完整 RESP 后取            |
 | sync.csv 落一行锚点               |
```

**T1 不上线**：主机不用它（只回 T2/T3），后处理从 CSV 拿——线上只传接收方本地
不可能知道的东西。MCU 仍要在发送前取 T1 并落盘（不发 ≠ 不取）。

offset/rtt **只在后处理算**（MCU 不算、不存）——单一真相，固件更薄。

## 3. 帧格式

```
0xAA | type | seq | len | payload | crc16 (u16 LE)
```

- `type` 只认 0x01（REQ）/ 0x02（RESP）；`seq`（u8）请求序号，RESP 原样回带，u8 回绕无害
- `len` = type+seq+payload 的字节数，**只认 2（REQ）/ 18（RESP）**
- `crc16` = CRC-16/MODBUS，覆盖 type 到 payload 全部字节：
  多项式 0x8005（反射）、初值 0xFFFF、输入/输出反射、结果异或 0x0000。
  实现自检：ASCII `"123456789"` 的结果必须是 `0x4B37`——两侧固件先对这个值再上链路
- 解析规则：找 0xAA → 读 type/seq/len（type、len 任一非法即回找头）→ 收满 → 验 CRC

| TYPE | 名称 | 方向 | payload（u64 LE，µs） | len | 帧总长 |
|---|---|---|---|---|---|
| 0x01 | TIME_REQ | MCU→主机 | 空（T1 本地落盘，不上线） | 2 | 6 B |
| 0x02 | TIME_RESP | 主机→MCU | T2_host, T3_host（16B） | 18 | 22 B |

**单位一律 µs**（u64 永不溢出）。MCU 时间源 = 自由运行定时器换算 µs
（16/32 位硬件计数器必须做溢出扩展合成 64 位，不复位、不被任务阻塞）；
主机统一 `clock_gettime(CLOCK_REALTIME)`。

**字节级示例**（seq=0x01，T2/T3 与 §6 CSV 同一组数）：

```
REQ : AA 01 01 02 A0 51
RESP: AA 02 01 12 B1 68 DE 3A 00 00 00 00 CE 68 DE 3A 00 00 00 00 55 4A
       │  │  │  │  └─ RESP 载荷: T2=987654321µs, T3=987654350µs (各 u64 LE) ─ CRC16
       │  │  │  └─ len (2 / 18)
       │  │  └─ seq
       │  └─ type (01=REQ, 02=RESP)
       └─ 帧头
```

对拍：先各算 `"123456789"` → `0x4B37`（CRC 互检），再对这两条帧逐字节一致。

## 4. 时间戳取法（20ms 预算下的简化约定）

统一"整帧事件前后"取，不做字节级补偿：

- **T1**：MCU 写 REQ 进 UART 前（本地取、落 CSV，不装进帧）
- **T2**：主机读完整 REQ 后立即
- **T3**：主机写 RESP 前
- **T4**：MCU 收完整 RESP 后立即

取戳约定不做字节级对齐：误差的系统部分（帧长不对称 ≈ 695 µs）由 §8 后处理补偿，
随机部分入 §7 预算。

**主机侧行为**（全部逻辑，就这些）：

```python
while True:
    frame = read_frame(fd, timeout=1s)      # 半帧/坏帧(验 CRC)直接丢，回找头状态
    t2 = now_us()
    t3 = now_us()
    write_resp(fd, frame.seq, t2, t3)
```

## 5. MCU 侧同步逻辑（fire-and-forget）

1. 每 5s 发 TIME_REQ（seq 自增），发完等 200ms：
   - CRC 校验失败 / 超时 / `resp.seq ≠ 本轮 seq` → **一律直接丢弃，本轮作废**，等下个 5s
   - 不重发、不记 GAP——锚点密度对漂移有 10× 裕量（§7），丢几个周期无感；
     断连由后处理从锚点间距发现（§8）
2. **对采集侧的唯一约束**：首次成功 SYNC 之前的 MCU 时间戳无法对齐——采集应在其后开始。

**seq 核对不能省**：迟到的旧 RESP 若与新 REQ 错配，offset 会错 ~秒级，
且错配时 rtt 可能 ≈0 或为负、躲过上限过滤——seq 比对是一行代码的保险，
后处理再加 `rtt > 0` 下界做双保险。

## 6. 落盘 sync.csv（MCU 侧，同步任务单一写者）

```csv
seq,t1_mcu,t2_host,t3_host,t4_mcu
1,123456789,987654321,987654350,123457000
2,128456789,992654321,992654360,128457020
```

- 每 5s 成功一次落一行（失败不落行，断连由后处理从锚点间距发现）
- **每次上电开新文件**（如 `sync_001.csv` 自增）——MCU 定时器上电清零，两段会话混进
  一个文件会让 t4 回退、后处理排序与间距告警全部错乱
- T1/T4 为 MCU 本地取，T2/T3 从 RESP 帧解出；单位全部 µs
- 主机不落任何文件；采集数据的落盘格式归采集侧，与本文档无关

## 7. 精度裕量账（含"5s 够不够"的答案）

| 误差源 | 量级 |
|---|---|
| 取戳约定的随机项（驱动/调度不对称；串行化系统偏差已补偿） | ~0.1–1.5 ms |
| 主机非 RT 调度抖动 | ~0.1–2 ms |
| USB 串口缓冲（FTDI 已调 1ms / CDC 类天然） | ~0.5–2 ms |
| 晶振漂移插值残差（50 ppm × 5 s） | ~0.25 ms |
| 坏帧/丢 SYNC 间隙（连丢 5 锚点 = 25 s） | ≤ 1.25 ms |
| **典型合计** | **< 3–4 ms**（预算 20 ms，≈5–7× 裕量） |

**5s 周期的账**：锚点间的 offset 漂移 = ppm × 间隔。50 ppm 下每 5s 只移动 0.25 ms，
线性插值残差 < 0.1 ms；连续丢 5 个锚点（25 s 间隙）也只有 1.25 ms。
**结论：5s 绰绰有余**——放宽到 30s（1.5 ms/间隙）仍在预算内。选 5s 不是为了精度，
是为了**断连定位粒度**（后处理能以 ±5s 精度定位断链时刻）和坏帧冗余（坏锚点滤掉后间隙仍然小）。

## 8. 后处理（PC 侧）

```python
import pandas as pd, numpy as np

sync   = pd.read_csv("sync.csv").sort_values("t4_mcu")

FRAME_US = 10 / 115200 * 1e6                       # 1 字节线上时间 ≈ 86.8 µs
sync["offset"] = ((sync.t2_host - sync.t1_mcu) + (sync.t3_host - sync.t4_mcu)) / 2 \
                 + (22 - 6) * FRAME_US / 2         # 补偿帧长不对称的系统偏差 ≈ +695 µs
                                                  # （REQ/RESP 串行时间不等，可算死的常数；
                                                  #   剩余误差 = 来回不对称/2，四时间戳拆不出来）
sync["rtt"]    = (sync.t4_mcu - sync.t1_mcu) - (sync.t3_host - sync.t2_host)
sync = sync[(sync.rtt > 0) & (sync.rtt < 100_000)]    # µs，双向界：>0 防错配，上限滤坏交换

spacing = sync.t4_mcu.diff()                          # 断连/丢周期：从锚点间距发现
if (spacing > 7_500_000).any(): print("WARN: 丢同步周期/断连，最大间隙 %.1fs" % (spacing.max()/1e6))
jump = sync.offset.diff().abs() > 3_000               # 阶跃告警：远超漂移界(0.3ms/5s)
if jump.any(): print("WARN: offset 阶跃(疑 NTP/坏锚点)：\n", sync[jump])

sync.to_csv("anchors.csv", index=False)               # 交付物：锚点表

# 采集侧用法（对齐任意 MCU 时间戳，数据格式采集侧自知）：
#   t_host = t_mcu + np.interp(t_mcu, sync.t4_mcu, sync.offset)
#   注意首尾锚点之外是夹持不是外推——采集应在首锚点之后开始（§5 的约束）
```

## 9. 验收

1. 静置 10 分钟：offset 序列**去掉线性趋势后**残差 (max−min) < 2 ms
   （判据必须去趋势：正常晶振 10 分钟的自然漂移就是 12~30 ms，趋势不是误差；
   去趋势一行即可：`np.polyfit(t4_mcu, offset, 1)` 拟合后取残差）；
2. rtt 健康核对（USB 转串口必看）：同步交换的 rtt 中位 < 5 ms——若中位 ~16 ms 且散布宽，
就是 FTDI latency_timer 没生效；
3. （可选，一次即可）MCU 打一个主机可见事件（日志行/示波器对拍），用锚点表对齐后差 < 20 ms。

## 10. 接受清单（明确不做，够用即止）

- 无版本号/握手/重连协商——单机单会话，重启即重来；
- 无多机寻址——将来 RS485 多挂 MCU 需加地址字段，现协议只服务单 MCU 单 UART；
- 主机不休眠/不挂起——CLOCK_REALTIME 会跳；
- CRC16-MODBUS——本帧长（≤22B）下漏检率可忽略，多比特突发错也能抓；
- 主机单线程读循环、无 RT 调优——0.1~2 ms 抖动已入预算；
- 不做最小 rtt 滤波、漂移拟合一类精细化——帧长不对称的系统偏差已在 §8 补偿，
  剩余误差是来回路径不对称（四时间戳信息量之外）；要再收紧走
  （最小 rtt 滤波 → GPIO/PPS 硬件对时，按此顺序）。
