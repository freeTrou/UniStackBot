## 1. 定位

- 上层:规划(MoveIt 等)、RL 策略、VLA 模型 —— **全部非实时、进程门外、视为不可信命令源**
- 本层:ros2_control 关节层底座 + **自建多协议通信主站**(CAN、IgH EtherCAT 等,按机器人选配、并行支持 —— 是主站矩阵,不是迁移路线)
- 下层:伺服驱动器(自带通信看门狗 = 安全链终点)→ 电机
- 目标:多形态通用实时框架;参考本体 Piper;第二形态拟用**轮式底盘**作试金石

一句话:**模型无关的控制核心,形态智能做成插件自带件,层间全部走数据契约。**

## 2. 总体架构

```
规划 / RL policy / VLA(GPU 进程,非实时,门外)
   │   参考入口(校验+时间戳)↓ / 观测出口(快照)↑
   ▼
┌─ 框架 core(模型无关)─────────────────────┐
│  交换原语(覆盖写+取最新) · OTG            │
│  环形日志 · 时钟抽象 · 控制描述契约         │
└───────────────────────────────────────────┘
   │   ros2_control = 关节层底座
   ▼
controller_manager(500Hz~1kHz,RT 化,FIFO 80 / 专用核)
   └─ SystemInterface 插件 ×N(每总线一个)
        │   同进程 · 双buff(覆盖写+取最新,seq+ts)
        ▼
主站线程 ×N(协议后端可插拔,FIFO 90 / 专用核)
   ├─ CAN 后端(如 Piper 协议)
   ├─ IgH EC 后端(ecrt,1kHz,DC,双层状态机)
   ├─ (vendor SDK 后端,预留)
   └─ 共同契约:语义状态机 · seq 看门狗 · 安全态
   │   CAN / EtherCAT CoE(按主站)
   ▼
驱动器(CSP 模式,自带通信看门狗 = 安全终点)→ 电机
   传感器从站/模块(IMU、F/T、系统量)→ 进 RT 快照
   (相机门外,走观测出口,只共享时钟域)
```

## 3. 关节层实时设计(已定)

### 3.1 进程与线程模型

| 项 | 决定 |
|---|---|
| 进程 | 单进程(插件、CM、主站线程同住);`mlockall` 一次全员受益 |
| **形态决策(2026-09-07 定稿,用户拍板,经公正审核)** | **主形态 B · 双线程**:线程1 = 总线+CiA402(FIFO 90/核A:收帧→解码→state_ex.publish→`out=cia402.step(sw, cmd_ex.take())`→急停旗直查→发帧→尾部复制进环形缓冲);线程2 = CM(FIFO 85/核B:read 取 state_ex、write 发 cmd_ex)。**交互仅两条通道**(state_ex/cmd_ex),v3 语义由线程1 的 step() 兑现。**审核后的诚实定位**:A 合并(市面主流)在延迟(0跳)/时序简单/排查面上胜,B 在 **RT 安全的结构强制**(read/write 物理上只有换缓冲,多协议后端想阻塞都没地方——对多主站矩阵的关键属性)/异构速率解耦/迁移成本(保现有代码)/可测性(fake 双向)上胜——**B = 用一格性能买结构强制与迁移经济,不是更先进**。B 成立的两个硬义务:①敲门级联必须兑现(1kHz 时,自由跑双线程=相位抽奖);②两条通道看门狗必须落码。**重审触发条件**:CAN 后端退场+单一 EC 总线+协议复用需求消失 → 回 A(step() 对象原样搬,不亏) |
| CiA402 协议线程 | **电机状态机唯一归属 + 复制者职责**:每拍完整闭环 = 消费状态快照(statusword)+ **消费控制值(cmd_ex,经状态机之手)** → 状态流转(使能链/故障/恢复/组语义)→ **颁布完整当拍输出** `DriveOutput{controlword, cmd_valid, cmd[]}` 经 ctrl_ex 下发。控制值**只在 OP_EN 且流转稳定时才获得 cmd_valid=true**——"经状态流转才能下发控制值"是构造性语义(值在状态机内才出生),非出口检查。**接口预留**:enable/disable(请求队列+状态回读确认)、quick_stop(原子旗)、控制值输入(cmd_ex)、反馈值输出(state_ex,反馈是观测不过状态机——有意的不对称)。尾部兼任复制者(快照推环形缓冲,RT 域仅三线程,IgH 禁止兼任);1kHz;FIFO 85,核 B(与 A 同簇) |
| **四层门卫结构** | 0=驱动器硬件(CiA402 语义:非 OP_EN 不执行,最终屏障)→ 1=EC 链路层(总线线程)→ 2=电机状态层(协议线程,门卫判定)→ 3=出口执行(总线线程)。软件门卫是纵深防御(不放垃圾/保持锚定),不是第一道防线——**故门卫判定滞后 1~2 拍可接受** |
| **线程交互规格(6 通道 + 级联, 讨论定稿)** | ①state_ex:IgH→CiA402+CM(双读者)②ctrl_ex{cw,cmd_valid,cmd}:CiA402→IgH(完整当拍输出)③cmd_ex:CM→CiA402(控制值经状态机之手)④quick_stop 原子旗:双源→IgH ⑤ingress:非RT→CM ⑥环形缓冲:CiA402 尾部→非RT。**CiA402 与 CM 无直接对话,IgH 是枢纽;控制值流经状态机才出生(v3 语义,用户模型)**。时钟定稿:**敲门级联**——IgH 收发完🔔CiA402,流转完🔔CM,流水线一拍走完,命令年龄恒定 1 拍+ε(自由跑的相位抽奖/骑墙点全部消失;前提=三线程计算和<1 拍,1kHz 余量充足;CM 等铃即原敲门制设计兑现;铃链活性由看门狗链兜底)。前提:优先级 IgH 90>85>80 天然匹配级联 |
| **看门狗链** | 每个生产者被其消费者监视:非RT 被 CM 盯(超时 hold+OTG)、CM 被 IgH 盯(cmd_ex 经状态机中继,陈旧→急停)、CiA402 被 IgH 盯(ctrl_ex 陈旧→急停)、IgH 被链路 watchdog+驱动器看门狗兜底——**整链无无人监视的生产者**。启动:级联使顺序天然确定(IgH 先起,铃链依次唤醒;gate 关闭期输出 hold) |
| **急停旁路(硬规则)** | quick_stop 为原子旗,IgH 线程每拍直查直发(cw=0x02);**双源置旗权**:总线层故障(IgH 自查)与电机层故障(协议线程),殊途同归于出口,≤1 拍生效,不依赖任何线程调度 |
| CM update 线程 | SCHED_FIFO 80,专用核 C;Humble 无优先级参数,**事后 RT 化**(/proc 扫线程名或 chrt 脚本),靠周期遥测验收 |
| 其余线程 | SCHED_OTHER,家务核;**禁止全进程 FIFO**(DDS 线程做 IO + FIFO = 系统卡死配方) |
| 主站线程寿命 | 与 CM 生命周期解耦:CM 进 ERROR 它继续活着维持安全态 |
| 准入清单 | 该进程只许 控制器插件 + 硬件插件 + 主站线程;推理/视觉/规划桥/重日志一律门外 |
| 内核 | 1kHz 阶段 PREEMPT_RT;RT 核 IRQ 迁离,必要时 isolcpus |

### 3.2 数据交换(双 buff)

- 语义:**覆盖写 + 取最新**;写满 buff → `idx.store(release)`,读侧 `load(acquire)` → 整块拷 → 索引复查(变了重读),recheck 做成计数器,长期应恒 0;
- 元数据:每槽 `seq`(**按写次数递增**,不按值变化)+ 时间戳(统一 `steady_clock`,不用 ROS 时间);
- 生死判据:命令 seq 停 → CM 死;状态 seq 停 → 主站死;
- 非阻塞:`read()/write()` 永不等待、永不加锁;
- 界 = 最旧 1 拍,是"取最新"语义的**结构性保证**(前提:读方拿住 buff < 一周期;框架级原语升三缓冲可删此脚注);
- 速率解耦:CM 500Hz(`update_rate` 可配)+ 总线 1kHz 合法;主站每拍发最新可用命令,中间设定值被跳过无害(CSP 绝对目标,驱动器自行插补);
- 实现为独立头文件,配 fake master 可脱离硬件单测。

### 3.3 双层状态机与生命周期映射

状态机**长在总线节拍里**(statusword 每拍进、controlword 每拍出),插件接口薄:

```cpp
bool       request(GroupTarget);     // 设目标,按 CiA402 转移图逐拍推进
GroupState state() const;            // 聚合状态(全组最低)
uint32_t   fault_axis_mask() const;  // 哪根轴 FAULT + 故障码
void       quick_stop();             // 无锁置位,下一拍生效(≤1ms 确定)
bool       wait_state(GroupState, timeout);  // 仅非实时回调用
```

| 插件回调 | EC 层 | CiA402 目标 | SUCCESS 条件 |
|---|---|---|---|
| `on_init` | 初始化、扫从站 | — | 从站认全、PDO 配好 |
| `on_configure` | → SAFEOP | → READY_TO_SWITCH_ON | `wait_state` 到位(含驱动上电等待) |
| `on_activate` | → OP | → OPERATION_ENABLED | **先锚定 cmd:=state 再发 0x0F**;全组 OP_EN + 0x6061 回读 = CSP |
| `on_deactivate` | 保持 OP | → SWITCHED_ON | 全组受控停住,高压保留 |
| `on_error` | 视故障层 | QUICK_STOP | 上报,不自行恢复 |

- **组语义**:臂是刚体链,无单轴容错;单轴故障 → 全组急停;

**控制值通路 v3(状态机中继一切控制, 讨论定稿——v3 语义源自用户模型)**:CiA402 线程每拍颁布完整输出,IgH 退化为纯搬运——

```
CM ──cmd_ex──▶ CiA402 线程:状态流转裁决 → DriveOutput{cw, cmd_valid, cmd[]}
                                                    │ ctrl_ex
IgH 出口(纯搬运):o = ctrl_ex.take();
                  tx(o.controlword, o.cmd_valid ? o.cmd : hold);
                  if (quick_stop_flag) o.controlword = 0x02;   // 唯一本地覆盖(链路层故障)
```

不变量(v3):G1 控制值到达总线 ⇔ 状态机流转至 OP_EN 且稳定(cmd_valid=true)——**许可位与值绑定同消息,无版本错配缝隙**;G2 cmd_valid=false 时 IgH 输出 hold(锚定),绝不 0/陈旧;G3 急停双源:链路层故障 IgH 本地覆盖(等不及状态机),电机层故障由状态机经 controlword 正常颁布;G4 状态认知同拍(值与判定同源,无滞后问题)。代价:命令年龄 +1 跳(自由跑最坏 3~4 拍,500Hz 位置模式无害)。接口预留:enable/disable(请求队列+状态回读)、quick_stop(原子旗)、控制值输入(cmd_ex 只被状态机消费)、反馈值输出(state_ex 直达 CM——反馈是观测,有意不过状态机)。
- 硬件激活语义:**JSB 常驻 active**(占用状态接口)防止换控制器时硬件 deactivate 掉使能;
- statusword 用位掩码解码(如 `&0x6F` 比对 0x21/0x23/0x27),禁止整字比较;
- 0x6060 模式先于使能配置并回读确认。

### 3.4 安全链(终点在硬件)

```
CM 掉拍/写停止 → 主站 seq 看门狗 → QUICK_STOP(0x02)
                                      │ 0x605A 选项码 = 受控减速+保持(安全态的硬件定义)
进程整体死亡 → IgH fd 关闭 → master 释放 → 帧停 → 驱动器自身看门狗兜底
```

恢复 = 两级阶梯:CiA402 FAULT_RESET → 不行则 EC 层重初始化 → **重锚定(cmd:=state)** → 重使能 → 控制器重新 spawn/activate。写成固定流程/脚本。

立场:**安全功能永远在硬件(STO/驱动器看门狗),软件看门狗只称"功能性保护"**。

### 3.5 时序预算与遥测

- 状态最旧 1 总线拍,命令最旧 CM 周期 + 总线拍,回路 ≈ 2–3ms;位置控制无影响(快环在驱动器内闭环);
- 失效边界:力控/阻抗、1kHz+ 接触任务、位置差分求导;
- 遥测:插件在 `read()` 统计实际周期(period 参数白送),非实时线程每秒报 min/max/avg;主站统计命令 seq 年龄;两边交叉定责;
- 验收线(**建议, 需定稿——讨论稿**):CM 周期 p99 < 2.2ms、命令年龄 p99 < 5ms、总线抖动 p99 < 周期 10%、seq 看门狗阈值 20ms、recheck 计数器长期为 0。

## 4. 多主站矩阵(并行支持,非迁移)

主站是**交换契约后面的可插拔后端**(模式照搬 sim_control 的 backend 抽象):一个 SystemInterface 插件按 URDF `<param name="master">` 选后端,每总线一个 hardware 组件,协议 × 机器人按需组合。

**所有主站共享的契约**(后端必须实现):
- RobotStateSnapshot 交换(覆盖写+取最新)+ seq;
- 语义状态机词汇(协议中立):READY / ENABLED / QUICK_STOP / FAULT —— CiA402 是 CoE 侧的映射,Piper CAN 协议是另一套映射,各后端负责翻译;
- 插件侧同一套接口:request / state / quick_stop / wait_state;
- seq 看门狗与安全态职责。

**各后端自持**:协议编解码、状态机映射、速率、参数、部署依赖。

**形态 B 的红利(2026-09-07)**:线程1 = 可替换槽位——骨架(生命周期/FIFO/state_ex+cmd_ex/step()权威/看门狗对/急停旗/能力声明/fake 可替换)协议无关写一次,CAN FD 后端=同骨架换内芯。三个 CAN 特有差异:①确定性来源不同(EC 调度制 vs CAN 仲裁制,1kHz 靠负载预算不靠配置,发帧策略:命令事件驱动+反馈轮询);②看门狗自己造(CAN 无 WKC,心跳超时检测 + 驱动器侧失能保护 = P2 落实);③时间戳降级(DC 采样级→收帧级,延迟档案 CAN 项更宽,训练侧引用)。

**统一总线接口(master.hpp)契约五要素(2026-09-07 讨论定稿)**:①生命周期 start/stop + `state()` 健康出口(插件据此映射 ros2_control ERROR),调度参数(核/优先级/周期)配置化;②语义状态词汇中立 + 能力声明(窄核心);③**快照语义为接口、双缓冲为内部实现**——`take_state()/publish_cmd()` 类型化,契约类型定义在总线抽象之外,SpLatest 可升级不破接口;④安全面统一:quick_stop 原子旗 + fault 查询跨后端同形;⑤零协议类型泄漏(P8)。三陷阱:最小公分母化(解药=能力声明)、协议词汇泄漏(解药=中立词汇)、一接口多路复用(解药=每总线一实例,CM 聚合)。**验收:fake master 是接口的第一个实现**——不带协议知识能实现完整,接口才算干净(P14/fake 先行)。
> **③ 的落地修订 (2026-09-17, 用户裁决)**: 契约类型已落地为 `unistackbot_interface` 的 **RobotFeedback/RobotCommand**(原草拟名 RobotStateSnapshot/JointCmd 弃用), 含冗余偏好/MIT 模式/分层结果码; 命名与分层均经用户逐轮裁决, 详见 unistackbot_interface/README.md。本文早期草拟名以落地为准。

**EtherCAT 错误面(八类,协议原生)**:WKC 每拍每从站归因 / 断链拓扑定位到段 / AL 状态码 / ESC 端口计数器(EMI+段定位)/ SM watchdog(P2 原生)/ DC 偏差 / 自锅 / mailbox abort;处理分级与 CAN 同构;双平台错误面测绘为装机自检。**完整设计独立成文:`docs/bus/ethercat_master_design.md`**(与 socketcan_master_design.md 平行,共享 master.hpp/协议层/三通道结构)。能力声明的差异(WKC/DC/拓扑定位 vs 心跳/无DC/收帧级ts)是两种总线真实能力的镜子,不是谦虚。

**协议层(形态无关设备语义, 2026-09-07 讨论定稿)**

**定位判据:协议层管"字节的含义",总线层管"字节的运送";形态多样性不属于协议层——包容度来自"形态盲",不来自"形态全"。**形态差异归属三层:描述/控制描述(谁组成机器人)、快照契约(状态表达模型)、协议层(单台设备对话)——协议层若出现 robot_type/arm_mode 即形态向下泄漏(最重罪)。

**六个组件**(全在线程1 内部):①数据模型(语义对象)②codec 编解码(**纯函数**,无状态无分配可离线单测;单位换算定点在此=rad↔计数,规范文档写死 SI 导出+定点)③状态机映射(中立词汇↔具体协议,step() 权威)④慢通道 mailbox(参数/配置/恢复等待,非RT)⑤节点管理(心跳消费/地址/能力协商)⑥**协议规范文档**(ID 分配表+帧格式+生命周期+寄存器表+版本规则 = 单一事实源,防两侧漂移的锚,等同 RL 仓库 schema 地位;版本字段从 v1.0 就要)。

**形态盲对象模型**:Bus(线程1 实例)→ Node(设备)四元组 {device_type: axis|imu|ft|battery|io|custom, capability 位图(上线握手读), registers(强制核心+扩展), cyclic 布局=f(type,capability)}。轴只是设备类型之一——机械臂=N axis,四足=12 axis+imu+电池,协议层对形态的全部认知就是"节点清单不同"。

**包容度来源 = 强制核心最小化 × 能力扩展**(破"交集将就/并集膨胀"死局):强制核心=位置+使能+故障+心跳(任何电机都做得到);可选扩展=力矩/速度模式、温度遥测、多圈编码器…(能力位声明,上层只依赖核心、按位探测)。抄 CiA402 验证过的结构(心跳消费者/SYNC 广播/NMT 生命周期/Emergency 帧/PDO-SDO 二分),不兼容但概念白拿。

**机器人组成 = 配置不是协议**:聚合器按控制描述 yaml(关节清单+总线映射, 讨论定稿)把协议层设备状态填进快照槽位;换机器人=换描述文件,协议层零改动——"第二台机器人成本"在协议层的答案是**一份描述文件**。

**验收 = 三个虚拟机器人**:7 轴臂 / 12DOF 四足(+imu+电池) / 轮臂(velocity 轮轴)——三份控制描述,协议层代码零改动全过 = 包容度通过;哪个机器人逼改协议层,哪个词汇就泄漏了形态。反模式:形态字段入协议、按机器人定义协议模式、核心塞高级语义、单位换算散落。

**可测性红利**:协议层 = 全链最可测层(codec 纯函数 golden frames 测试、状态机转移表全覆盖、decode 模糊测试、mailbox 注入测试)——零硬件测到 90%,与总线层"先证据后代码"互补。

**能力声明**:每个主站诚实声明能力(有无硬件看门狗、支持 reset/set_state 与否)—— 沿用 gz 适配器"能力矩阵(诚实声明)"的先例;P2(驱动器看门狗确认)按主站逐型号落实。

**速率几何**:CM 全局 update_rate 取最快总线(如 EC 1kHz),慢总线主站线程自持节奏、靠取最新语义衔接。

**IgH EC 后端要点**(选型已定):
- ecrt 用户态 API 在主站 RT 线程内跑总线循环(ioctl 每拍),PREEMPT_RT 上 1kHz 工业验证过;不上内核态开发;
- DC:循环内每拍 `application_time` + `sync_slave_clocks`;
- 崩溃语义:进程死 → fd 关 → master 自动释放 → 帧停 → 驱动器看门狗跳,安全链天然不断;
- 部署成本:内核模块跟内核版本(DKMS)、master 实例预留、网卡绑定 —— 写进 bring-up 文档。

**多总线同机**:每总线一个组件,激活/故障按总线隔离;多总线 DC 不保证同源,RobotStateSnapshot 按总线带 ts,合并时对齐。

### 3.7 传感器接入(RT 快照的一等公民)

控制域硬件不止驱动器:关节编码器/关节力矩(驱动器 PDO)、IMU、足端/腕部六维力、接触、电池/温度进 RT 快照;相机/深度**不进快照**,走观测出口、只共享时钟域。

**与主站矩阵正交**:master 后端是协议维度抽象,`System`/`Sensor` 组件是 ros2_control 维度分类,两者自由组合——同总线传感器经 System 组件导出任意命名 state interface(零新增概念);专线传感器(如 IMU)经 `SensorInterface` 组件复用同一 master 后端,白得 semantic_components 生态。

**三条纪律**:
- **时间戳打"物理时刻"的最好近似**(传感器端 EC DC/硬件触发 > 主站收帧 > CM read);EC DC 提供采样级时间戳,CAN 只能收帧打戳(抖动表征进延迟档案);
- **跨源时基对齐**:每源独立 ts + 偏移标定流程(静置+激励)+ 交叉偏斜常驻遥测(IMU vs 关节差 2~3ms 是腿式速度估计噪声的经典疑难);
- **多速率**:取最新 + 每源 seq(可判丢样率);需全流时再升级主站预积分或小环形。

**安全联动**(功能性保护,安全功能仍只在硬件):电池跌落 → 受控停;过温 → 降额/停;关键传感器失联(双足的 IMU)→ 状态机故障路径,降级行为显式设计。

**快照 v2**:每源统一头 `{seq, ts, alive}`,合并 = 控制拍取各源最新 + 健康判定;结构 versioned。

**接入判据与边界**(电池/相机之问):数据进不进 RT 快照,看"从哪来 + 谁以什么频率消费";**接入框架 ≠ 进 RT 快照**,框架有两条接收路径(RT 快照 / 非 RT 监护 + 状态机 request)。
- 驱动器温度:在驱动器 PDO/SDO 里,主站顺手读(SDO 慢读走主站后台上下文,不占 RT 循环);**进快照 ≠ 1kHz 更新** —— health 段慢刷新、每源 ts 自带年龄,每拍搭车传输;
- 电池:在控制总线上(EC 电池模块 / CAN BMS)则顺手进快照;独立接口(USB/I²C BMS)不为它造 RT 通道 —— 非 RT 监护线程(10~50Hz)读取,经状态机 request 触发保护(电压跌 → 受控停);
- 相机:**数据流门外,时间纪律门内** —— 图像不进 RT 域(传输用压缩/共享内存,不走裸 DDS);框架管三件事:时钟对齐(相机 ts ↔ 控制时钟域)、可选硬触发(EC DC 同步输出脉冲,曝光锁相控制拍)、相机链延迟档案(曝光 → 策略可见,量测后喂训练)。

## 5. 框架层构思

### 5.1 命令阶梯

```
L4  任务/语言指令(VLA,GPU,5~50Hz)    ── 门外
L3  末端位姿流(50~100Hz)              ── 位姿消费器(IK,形态插件自带模型)
L2  关节目标流(RL policy,50~500Hz)   ── 推理进程,门外
L1  关节接口(1kHz,ros2_control)      ── RT 域
      └─ 每级边界 = 同一交换原语 + OTG 变速率 + seq 陈旧看门狗
```

### 5.2 核心原语与标准组件

- **交换原语**:覆盖写+取最新+seq —— 一个原语,N 个边界(主站↔CM、策略↔控制、观测下行、遥测);参考 `realtime_tools::RealtimeBuffer`,框架级版本用三缓冲;
- **OTG(在线轨迹生成,Ruckig 类)**:反应式目标的 v/a/jerk 受控生成;三处复用:遥操作、底盘速度平滑、策略降频(50Hz 输出禁止零阶保持直灌 CSP);
- **环形日志**:1kHz 调参数据,RT 写 + 非 RT 落盘;
- **时钟抽象**(**讨论稿, 需定稿**):三个时间域(steady_clock / EC DC / 仿真 /clock),快照 ts 用哪个域、在哪换算,未决。

### 5.3 控制器层分层

**算法纯 C++ 库(不含 ROS 类型,可单测、跨形态复用)+ 薄适配器(ros2_control 控制器插件,只做数据搬运)**。

### 5.4 控制描述契约(URDF 立场)

| URDF 角色 | 消费者 | 是否必需 |
|---|---|---|
| ① 运动学描述(link/mesh/轴向) | 仿真、TF、RViz、MoveIt、IK | 可选(= 仿真适配器) |
| ② 控制描述(`<ros2_control>` 块) | ros2_control resource_manager | 必需(仅语法壳,不含运动学) |
| ③ 关节契约(名字+接口+限位) | 主站/交换层/算法层 | 框架核心,URDF 无关 |

原则:**框架契约 = 控制描述;URDF 只是载体之一;控制核心模型无关,模型由形态插件自带**。
对外一句话:不带模型也能控制(关节空间,仿真可选),带上模型才能规划(笛卡尔/腿式智能)。

无 URDF 机器人三级支持:
- L1 只有关节清单 → yaml 生成最小控制描述,关节空间全功能;
- L2 黑盒平台(vendor SDK)→ SystemInterface 包 SDK,SDK 顶替主站位置;轮子按 diff_drive 惯例建模虚拟关节;
- L3 完整 URDF → 全功能。升级路径单向无损:只补 description,控制侧零改动。

### 5.5 插值器地图

```
规划:稀疏轨迹 →【JTC 插值,现成】→ 500Hz 设定值流
   →【禁止插值区:插件/主站,取最新原样转发】
   →【驱动器 0x60C2,窗口=命令周期(2ms)】→ 平滑电流
```

纪律:插值只长在速率/语义变化边界,每处一个,不许叠。

### 5.6 真机点火顺序(四步,未绿不许跳)

fake master 冒烟 → 真总线 state-only(不使能)→ 使能 + 力矩限幅 → 小幅运动。

## 6. RL / VLA 接入

核心认知:**推理永远不进 RT 域;策略输出与摇杆同级信任。**

### 6.1 参考入口(reference ingress)

非实时侧:订阅(DDS/SHM/跨机可插拔)→ **校验**(限位/工作空间 clamp、速率限制)→ 盖时间戳 → 写入交换原语;RT 侧:取最新 + 陈旧检测。
策略死/疯/越界由入口接住:过期 → 保持 + OTG 受控减速,与命令断流同路径,**不新增安全机制**。
校验模式平移自 `SimControlServer` 的 Validator(拒绝并说明原因)。

### 6.2 观测出口(observation egress)与 sim2real

- RT 快照(RobotStateSnapshot:关节 + IMU + FT + 系统,versioned)→ 环形缓冲 → 固定布局观测发布 → 策略进程;
- **单一 schema 双侧生成**:一份 yaml 同时生成 Python 训练侧与 C++ 部署侧的结构体/打包代码 —— sim2real 第一大翻车原因是两侧观测不一致(顺序/单位/归一化/坐标系),从结构上杜绝;
- sim2real(仿真到现实):RL 在仿真练、真机部署;差距来自接触/摩擦/延迟/噪声建模不全。框架贡献三件事:观测契约、延迟真实性(训练侧建模 20–50ms 回路延迟,依据即本文时序预算)、MuJoCo 后端迭代速度。

### 6.3 待定(新增疑虑)

1. 推理与控制同机(核隔离)还是分机(Jetson+台式机)?GPU 驱动中断/线程须避开 RT 核;
2. 图像是否进观测(相机→策略延迟链、触发同步、时间戳对齐)?

4. 策略热切换(运行中换模型)是否需要?需要则入口带版本握手。

## 7. RT / 非 RT 分域规约(完整设计)

**判据**:"晚了有没有物理后果"——会摔/撞/失控 → RT;只是体验差 → 非RT。防两个误判:计算重 ≠ 非RT(WBC 在闭环里);频率高 ≠ RT(策略 50Hz,入口接得住)。

**域成员**:RT = 主站、CM+控制器、状态估计/WBC、复制者(轻,低优先级);非RT = MPC/RL/VLA 推理、规划、日志落盘、遥测发布、诊断、UI、一切 DDS 机制。

**物理分配**:控制进程 = RT 域载体(CM+插件+IgH 传输+CiA402 协议+复制者,准入清单);RT 核 2~3(隔离+nohz+RT 内核,1kHz 下内核前置 §RT 手册 1.2);优先级 **IgH 传输 90 > CiA402 协议 85 > CM 80 > 复制者 60**(传输与协议线程同簇不同核);其余进程 SCHED_OTHER 家务核。

**边界 = 六种流量,各配原语与契约**:

| 方向 | 流量 | 原语 | 契约 |
|---|---|---|---|
| 非RT→RT | 参考命令 | SpLatest | ingress 三件套:clamp/限速 + ts + 陈旧看门狗(超时→hold+OTG 减速) |
| 非RT→RT | 生命周期请求 | SPSC 队列 | 命令+状态机回读确认 |
| 非RT→RT | 配置参数 | activate 时冻结 | 运行中不热改 |
| RT→非RT | 快照消费 | 复制者→环形缓冲 | 每帧 seq+ts;慢消费者不碰 RT buffer |
| RT→非RT | 日志 | ring + drain | 满则丢,绝不反压 RT |
| RT→非RT | 故障事件 | 事件队列 | **不可丢**(满则记数报警) |

边界三铁律:每点必有 seq/ts 与单一写者;RT 侧接口无锁无阻塞;校验在 ingress 过境时做,不在消费处。

**时间**:RT 域单源 steady_clock;跨界不换算,数据带 ts 走;打戳在诞生处;域内可锁相(敲门),域间永不。

**启动/关闭**:RT 先起(READY→锚定)→ 非RT 后起 → ingress 才开闸;关闭反向。非RT 永远不能先说话。

**降级矩阵与方向性原则**:非RT 死 → hold+减速;复制者死 → RT 无感;CM 死 → 看门狗+两级恢复;主站死 → 驱动器兜底。**RT 域必须能在非RT 缺席时独立维持安全,反之不要求**——这是"实时区域"的真正定义。

**验收**:每个跨界点一条年龄/丢帧指标(参考年龄、obs 丢帧、日志丢弃、事件积压)+ RT 周期指标,挂 §3.5。

**反模式**:RT 循环直接发话题;跨界共享可变对象;非RT 持 RT 要的锁;ingress 无校验;RT 安全依赖非RT 在场;"先都塞 RT 以后再分"(漂移方向永远是 RT 域越长越脏)。

母题:ingress/egress 就是放大到系统尺度的 SpLatest——不共享状态,只传递快照。

## 8. 设计原则(八条)

1. **契约式边界** —— 层间只传数据契约不传函数调用;同进程是部署选择而非架构依赖,逃生舱常开;
2. **覆盖写 + 取最新** —— 一切 RT↔非RT、慢↔快边界统一语义,界 = 一拍;
3. **谁确定谁观察** —— 确定性一方监视不确定一方(主站看门狗看 CM,插件遥测量 CM);
4. **安全终点在硬件** —— 软件看门狗只叫功能性保护,永不自称"安全";
5. **控制核心模型无关** —— 模型是插件自带件,不是框架前置条件;
6. **状态机长在总线节拍里** —— 接口薄,转移由节拍推进,CM 死了状态机自己走完;
7. **框架成败 = 接入第二台机器人的成本** —— 每个决策过"轮式底座塞得进吗"试金石;
8. **一切有界** —— wait 带超时、join 带超时、看门狗带阈值、遥测带验收线。

## 14. 形态与算法边界 (2026-09-09 讨论定稿)

> 五形态控制分析 + 扩展性设计 + 算法归属裁决的收敛记录。
> 核心结论: **形态进数据, 算法进阶梯, 演进走版本; 命令模式属驱动器轴与形态正交;
> 算法双通道接入 (外部进程 / CM 插件), 框架只产通用算法 + 接入点 + 接口。**

### 14.1 五形态控制分析 (摘要)

难度两跳: 臂→轮式小跳 (加速度命令+OTG); **轮式→四足性质跳** (平衡成为控制问题:
力矩通路/1kHz 硬性/IMU 进 RT 快照); 四足→双足只是严苛化。框架的真正考题是四足。

| | 机械臂 | 轮式 | 四足 | 轮臂 | 双足 |
|---|---|---|---|---|---|
| 稳定性 | 静态 | 静态 | 静→动两档 | 组合 | 全动态 |
| 主导命令 | CSP | **CSV** | CSP→**五元组** | CSV+CSP 混合 | 五元组 |
| 重头算法 | IK+规划 | 运动学+OTG | 步态/MPC/WBC | +浮动基座IK | 四足超集 |

### 14.2 命令模式正交裁决

**形态轴与驱动器轴正交, 严禁互相推断** (分析者最易犯的错, 两轮内栽两次):
- 形态决定算法算出什么 (力矩为主 vs 位置为主)
- 驱动器决定命令以什么格式被执行 (CSP/CSV/MIT/CT, 上线握手读能力位图)
- 同一形态配任意驱动器皆合法; 组合合法性由运行期能力查询判定

传输契约: **带模式标签的变体** (JointCmd{mode, payload}), 新模式 = 加枚举加参数集的加法演进;
模式切换的运行期安全语义 (切换瞬间目标来源) 归协议线程状态机, 待细化。

### 14.3 扩展性三机制

1. **形态进数据**: 新形态 = URDF + 节点清单 + 算法插件 + 参数, 框架包 diff=0;
   验收 = 每次接入后 git diff 框架核心 (设计原则 7 的可度量版)
2. **算法进阶梯**: L1~L4 按**控制周期分档**归类 (决策周期是物理结构, 不随算法流派变),
   框架赌分层稳定不赌算法流派; 新算法 = 门外新客户, 出错被 OTG/看门狗拦在门外
3. **演进走版本**: 契约版本化, 大版本升级共存旧版; 形态字段入协议 = 最重罪

### 14.4 算法双通道接入 (团队协作的边界定稿)

| | 通道 A: CM 插件 (进程内) | 通道 B: 外部进程 (门外) |
|---|---|---|
| 适合 | 计算密集+行为确定 (WBC/确定性控制律) | 非确定/推理型/低频 (RL/VLA/视觉/遥操作) |
| 频率 | 1kHz RT 域无损 | 50~500Hz + OTG 限速 |
| 代码位置 | **算法团队仓库** (框架只提供插件模板+文档) | 算法团队仓库 |
| 安全 | RT 纪律模板内置 | 校验+OTG+超时 hold |

- **WBC 归属裁决** (讨论定稿): 通道 A/C 例外路径**永久保留为一等公民**——
  计算密集但行为确定的算法 (确定性 QP, 无学习随机性) 内化进 CM 无损 RT;
  框架的交付 = **插件接入模板** (RT 纪律内置, 算法团队在自有仓库实现派生类)
- 框架自研算法边界: **只做通用算法** (OTG 接入器/正运动学/按需评估现成 IK·动力学库),
  形态专属算法 (步态/WBC/ZMP/轮式解算) 永不进框架仓库
- 对上接口: ingress topic (L2/L3) + state exit topic —— 外部进程算法的接入契约
- 仓库定位修正: unistackbot_controller 只放通用基础设施控制器, **保持空壳是正确状态**

> **⚠️ 修订 (2026-09-17, 裁决变更)**: 上面两条"永不进框架仓库 / 保持空壳"的定位**废止**——
> unistackbot_controller 确定为**算法工程的承载包**: 自研算法控制器 (如 Cartesian IK 运动控制器)
> 与通用基础设施同仓演进。双通道接入语义不变, 仅对外部团队算法成立 (表中"代码位置=算法团队仓库"
> 仅指外部团队的算法); 自研算法位置 = unistackbot_controller 本包。形态盲纪律 (库不含机型知识,
> 机型只是 URDF 数据) 不变。

### 14.5 框架侧算法清单 (定稿)

| 组件 | 定位 | 触发/优先级 |
|---|---|---|
| OTG 接入器 (含 L2/L3 入口) | 安全链成员, 门外命令的唯一大门 | 真机接入前必须 |

### 14.6 挂账

- ARM 真机验证 (三原语家族)
- ulog v1.1 多实例 (§13 评审稿, E1-E5 待拍板)
- 模式切换运行期安全语义 (切换瞬间目标来源, 协议线程状态机)
- **命令安全闸 command_gate (2026-09-17 讨论稿, 非最终形态——重启时作为输入方案, 需重新审核)**
  - 触发背景: P1.4 (IK) 安全讨论中确立的职责分层——**IK 内部纪律 (限位目标函数/分支粘性/失败不输出) ≠ 框架强制保证**; 后者必须独立于算法存在, 算法可换、闸不可换 (四层门卫哲学在命令通道的落法)
  - 核心模型 (已达成共识): **最小信任接口**——不论上游 (IK/RL/遥操作) 内部如何计算, 到达下发的永远是关节弧度值向量; 安全域 = 限位盒 ∩ 步长盒 ∩ 有限性, 校验 O(n) 穷举、可完备——"一定可确保安全"的数学根据
  - 提议结构 (待定型): 每拍无锁校验——① 限位逐关节 ② 步长逐关节 (相对上一拍下发值) ③ NaN/inf → 该关节保持上一拍; **两段式**: 可修偏差 (贴边/小幅超) → clamp + 计数 + 上报 (修正放行); 不可修偏差 (离谱量级) → 整帧拒绝保持上拍 (修正是安全的发生, 静默修正是故障的隐藏)
  - 提议落点: controller 层命令通道 (RobotCommand → 闸 → ros2_control 的必经之路); 算法控制器模板将"过闸"列为标配纪律
  - 待拍板项: 两段式阈值 (真机调参项, 模拟阶段仅给保守默认); 最终落点 (controller 命令通道 vs 其他); 与 OTG 摄入门的分工 (闸=位置级边界, OTG=速度/加速度/jerk 动力学滤波)
  - 验证方法 (已共识): 纯框架单测——乱值进出出口必限内 / NaN→保持上拍 / clamp 必伴随计数, 与算法完全解耦
- 本节随讨论继续充实

### 15.3 分歧点 (自主选择, 业界背书)

**Form B 双线程** (总线 I/O 不在 CM loop): 腿式业界主流是独立 RT master (微控制器/专用进程)
+ ros2_control 退居监督层 (legged_control/MIT 系/Reddit 社区讨论)。本框架 = **进程内线程版**
同一思想: 少进程隔离, 省 1 跳延迟, 保单进程 mlockall; 结构强制的 RT 安全 (read/write 只有换缓冲)不变。

**自研三原语而非 realtime_tools**: 多工程复用 (非 ROS 依赖) + seq 看门狗/丢旧保新/丢新计数
等扩展语义 realtime_tools 不具备。realtime_tools 的 **RealtimePublisher** 在 OTG 接入器
实现时按需引用 (state 出口 topic 的 RT 安全发布), 作为框架对外接口的实现细节。

### 15.4 对外接口预留 (RL/外部算法进程 = 第一消费场景)

**推理永不进 RT 域** —— RL 策略/VLA 是外部进程, 与框架的唯一关系 = 两类 topic 契约:

| 方向 | topic | 频率 | 框架侧处理 |
|---|---|---|---|
| 命令 ingress | 观测/命令消息 (RL 侧定义 schema) | 50~500Hz | CM 内 OTG 接入器: 校验 → clamp → 限加速度 → cmd_ex |
| 状态 egress | RobotStateSnapshot 发布 (realtime_tools::RealtimePublisher 或复制者) | 1kHz | RT 线程零阻塞发布 (锁自由交接) |

设计输入 (RL 接入时兑现):
1. OTG 限幅参数 = 策略部署配置的一部分, 与训练侧联合标定 (训练器仿真器内加同款平滑, 让策略见过平滑);
2. OTG bypass 对比开关 (debug): 排查"策略真机效果差"的第一排查项;
3. 命令消息 schema 由 RL 侧定义 (框架不定义算法语义), 框架只负责校验/限速/超时 hold;
4. 跨进程低延迟通道演进位: 共享内存 (iceoryx 方向评估), DDS topic 为 v1。

## 16. 命令平滑与率对齐（2026-09-23 四裁决收口）

> 背景: 笛卡尔 sweep 大幅运动落地后, "谁负责平滑" 从隐性约定升级为显式架构裁决。
> 同日组件层落地 `CartesianShaper`（笛卡尔侧能力补齐）。

### 16.1 频率拓扑（裁决一: CM=总线同频相位锁定）

```
上层算法 (demo/MoveIt/RL/VLA)      10-100Hz    ← 唯一"慢"的层, 命令流
      │  值通道 (KeepLast1)
      ▼
CM IK 伺服 + JS = 控制环 = 总线     同一频率    ← 仿真 500Hz; 真机=总线频率 (DC 锚定)
      │
      └─ 一个节拍: [总线收 → read() → update()(IK/插值档) → write()(防线) → 总线发]
```

- **总线就是时钟**: 同频 + EtherCAT DC → 控制环锁在总线节拍上, 节拍源唯一
  （与 bench "总线=DC 锚定节拍源不可移相" 裁决同构）。
- **跨频桥接问题整个消失**: 双频解耦拓扑（bench sp_latest_chain 研究的撞窗/相位账）
  在本裁决下不成立, 实验保留为反事实记录。
- 仿真 `update_rate`（当前 500Hz）与真机总线频率是**同一个旋钮**, 切换零代码改动。
- 核1 单环锁总线节拍; 核2 预留身份变为通用计算预留（CM worker 等）。

### 16.2 透传原则（裁决二: 频率对齐即透传）

> **插值只存在于率失配处; 频率对齐即透传。**

| 上层给什么 | 频率 | 框架做什么 |
|---|---|---|
| 关节角流 | = 总线频率 | **透传**（零插值零整形; 满速流 + 界内命令时防线静默, 输出=输入） |
| 关节角流 | < 总线频率 | JS 桥接: **`ruckig`（链上默认, 2026-09-23 A/B 定音: 同轨迹 dv/拍 平滑 42-100×, C2 兜底第三方粗糙输入）**/ `hold`（零阶+速度界, 保留为满速透传语义档） |
| 末端位姿流 | 必然 < 总线频率 | CM 桥接: 每拍 IK + 步长饱和（IK 即位姿→关节的率适配器） |

- **透传 ≠ 裸传**: 透传指不注入形状; write 层防线（NaN 门→限位→步长饱和）永远在。
- **平滑的责任永远在"跑得慢的那方"**（或它显式委托的桥接服务）; 框架对形状零主张。

### 16.3 OtgStream 唯一入口（裁决三）

全工程 Ruckig 只经 `unistackbot_common/ruckig` 的封装进入（裸 include `ruckig.hpp`
仅允许出现在本组件内; 现状已零违例）:

- 单点防御（-101/-110/-111 防线写一遍审一遍）、单点 RT 纪律（零 malloc 补丁一份）、
  契约简单可验（Ok/Hold, Hold 输出恒有效）、许可/升级单点（MIT vendored 冻结）。
- **作用域 = jerk-limited 整形的唯一入口**, 不是"一切运动生成"的入口: CM 步长饱和、
  write 层防线是安全钳位不是平滑, 永远不走此入口（透传原则）。
- 笛卡尔能力**组合纳入**: `CartesianShaper` = 位置 OtgStream<3> + 姿态锚点切空间
  OtgStream<3>（`r = log(anchor⁻¹·q)` → R³ 与位置同构）, "唯一入口"字面成立。
  设计教训: 每拍 reset 注入实测状态不可行（reset 强制下拍重算 → 推进/停滞交替）,
  流式整形必须保持底座状态延续。
- OTG a/j 限值 = per-robot yaml 机型资产（`max_acceleration`/`max_jerk`; URDF 无此项,
  速度限值在 URDF 保持单一事实源）。

### 16.6 语义统一: 终点=流的一档频率（裁决五, 2026-09-23 深夜）

**每条末端位姿消息 = 最新终点。** 流式跟踪与终点对齐是**同一契约的两个频率档**
（50Hz=跟踪、10s 一条=对齐、总线频率≈透传）, 不是两种功能——上游消息频率是参数,
不是形态。由此:

1. **唯一可变维度 = 可打断性, 默认可打断且为原生语义**: OtgStream 每拍从当前状态
   (位置+速度+加速度) 重规划 C2, 新目标即无缝变形, 无需等走完、无台阶。
   "不可打断"（走完当前段才吃下一个）**不进控制器**——上层自律（等 status 收敛
   再发下一条, demo 逐点模式即此）, 控制器加排队/拒绝逻辑反而违背点流语义。
2. **统一形态 = CM 输出级 OtgStream 化**:
   `~/target (点流) → 每条一次 IK（回调线程, 种子=实测, 墙钟预算 50ms 档）
   → SpLatest 关节终点 → RT 环 OtgStream 追最新（C2）→ 接口输出`。
   - 每条消息重解（种子=实测）保闭环补偿——mujoco 重力下垂按消息率追回;
   - RT 环退出 IK（500µs 预算难题与 worker 冷启动机制整体消失）, 只剩
     OtgStream+FK(实测, status 误差)+发布——比旧 CM 更便宜;
   - 关节 max_velocity 由 OtgStream Limits 原生约束, 步长饱和降级为安全钳位底线;
   - IK 结果码/min_sigma 随通道载荷进 status（遥测面不缩水）。
3. **OTG 门退役**: 其架构（回调 IK+OtgStream）即 CM 的新输出级, 独立插件与
   "手动 spawner 拉起"流程一并移除; JS 保持关节域不变（CM 不再经 JS, 接口自认领）。
   双重整形接缝（门 OTG→JS ruckig 串联）随之消失。
4. **验收门**: mock E2E（up/axes/sweep 三 pattern + 不可达拒绝）+ mujoco 回归
   （物理链下垂补偿按消息率验证）+ WCET 前后对比 + 频率矩阵重跑基线。
