> 价值观先行:**普通软件优化平均值(吞吐、均值延迟),实时软件只优化尾部(最坏情况、抖动)。实时 ≠ 快;实时 = 有界(bounded)且可预测(predictable)。一个平均 10µs 但最坏 5ms 的系统,不是"99% 实时"的系统——是 0% 实时的系统。**

## 支柱 1 · 节拍与调度(系统的心跳合同)

### 1.1 需求

- 全系统**单一节拍源**(本项目:controller_manager 的 update_rate,总线线程的 1kHz 循环各自有自己的节拍,但节拍之间的关系必须被显式设计——级联或解耦,二选一,不许"刚好碰巧");
- 每个周期任务有**显式的周期 T 与最坏执行时间 WCET**;
- 优先级安排有依据(不是拍脑袋的数字);
- **可调度性有结论**:一组任务在最坏情况下是否都赶得上截止期,要有答案(算出来的或测出来的)。

### 1.2 理论基础:Liu & Layland(1973)

周期任务集在单核上按固定优先级调度,两条经典结论:

- **RMS(速率单调)**:周期越短,优先级越高——这个朴素策略是理论最优的固定优先级方案;
- **可调度利用率界**:n 个 RMS 任务,总利用率 `U = Σ(C_i/T_i) ≤ n(2^(1/n)−1)` 时**保证可调度**。n→∞ 时 U ≤ ln2 ≈ **69.3%**。

例:主站 C=300µs/T=1ms(30%)+ CM C=200µs/T=1ms(20%)= 50% < 69% → 理论保证可调度。若再加一个 30% 的任务 = 80% > 69% → **不是一定失败,而是不再有保证**——每一拍都是实验,实时变成信仰。

固定优先级下还有更精确的反应时间分析(`R_i = C_i + Σ_{j<i} ⌈R_i/T_j⌉·C_j`,迭代求解)——需要精确 WCET 时用它,但工程上 69% 界 + 实测 WCET 通常够。

### 1.3 Linux 机制

| 机制 | 干什么 | 注意 |
|---|---|---|
| `SCHED_FIFO` | 固定优先级抢占,同优先级**不轮转**(跑到阻塞为止) | 本项目主用;两个同优先级 RT 线程挤同核 = 强制轮转 = 抖动,禁止 |
| `SCHED_RR` | FIFO + 时间片轮转 | 基本不用 |
| `SCHED_DEADLINE` | EDF + 带宽隔离,(runtime, period, deadline) 三元组,内核**保证配额** | 多 RT 任务需要理论保证时用;与 FIFO 混用的优先级语义要小心 |
| `sched_rt_runtime_us` | RT throttling:默认 RT 合计最多 950ms/1000ms | **经典翻车点**:RT 线程忙等 → 被限流 → 神秘 50ms 停顿。上电先检查 |
| `taskset`/`sched_setaffinity` | 驻核 | RT 核与家务核分离 |

### 1.4 代码模式

```c
// RT 周期任务的完整出生序列(顺序有讲究)
pthread_setschedparam(self, SCHED_FIFO, &(struct sched_param){90});  // 先提优先级
cpu_set_t set; CPU_ZERO(&set); CPU_SET(RT_CORE, &set);
pthread_setaffinity_np(self, sizeof(set), &set);                     // 再驻核
mlockall(MCL_CURRENT | MCL_FUTURE);                                  // 锁内存(支柱2)
uint64_t next = now_ns();
for (;;) {
        next += PERIOD_NS;
        cycle();                                                     // 有界执行
        struct timespec ts = ns_to_ts(next);
        clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &ts, NULL);  // 绝对睡眠
        if (now_ns() > next + SLACK_NS) overrun_count++;             // 自证守时(支柱7)
}
```

四个细节:①先设调度再进循环(循环内不做"设置"类 syscall);②**绝对时间**睡眠(TIMER_ABSTIME,误差不累积、不吃 timer slack);③overrun 自检(每拍自证守时);④`next += PERIOD` 而不是 `next = now() + PERIOD`(后者把执行时间永久累积进节拍)。

### 1.5 失败形态

- 优先级倒挂:高优先级等低优先级持有的锁 → 卡死或抖动(支柱 3 的 PI 锁救);
- 利用率超 69%:负载下某拍周期性超时(平时看不出来,压力测试才爆);
- 忘记 RT throttling 检查:神秘周期性 50ms 空洞。

### 1.6 验收

- 每任务 WCET 实测(不是估)并留档;
- 长压(≥1h 满负载)overrun 计数 = 0;
- cyclictest 同核基线对比无退化。

### 1.7 我们栈的落点

优先级阶梯 IgH 90 > CiA402 85 > CM 80 > 复制者 60;两 RT 核同簇;准入清单(进程内只许控制器插件+硬件插件+主站线程);`update_rate` 为 CM 节拍,总线线程自持节拍,两者关系显式设计(级联或解耦)。

## 支柱 2 · 内存纪律(RT 路径上什么都不能发生)

### 2.1 需求

周期路径(每拍执行的代码)上,**任何可能引入不可界定时长的操作都是违禁品**:

- 动态分配/释放(malloc 可能触发缺页、页表锁、甚至 sbrk 系统调用);
- 阻塞 IO、日志、printf(内部有锁,可能分配);
- 异常抛出/捕获(C++ 异常路径可能分配、展开栈时间无界);
- 无界循环/递归(时间上界丢失);
- 页面未锁死(即使不 malloc,首次访问任何页都是缺页 = 磁盘级延迟)。

### 2.2 "理论":缺页的代价谱

| 事件 | 量级 |
|---|---|
| 缓存命中 | ~1ns |
| 跨核缓存搬运 | ~40-100ns |
| 主存访问(已锁页) | ~100ns |
| **次缺页(页在内存,需装表)** | ~1-10µs |
| **主缺页(swap/磁盘)** | **1-10ms** ← 一次就毁掉一个月的预算 |

mlockall 的意义:把"主缺页"这个量级**从系统里物理删除**。

### 2.3 Linux 机制

- `mlockall(MCL_CURRENT | MCL_FUTURE)`:锁现有+将来所有页(注意 MCL_FUTURE 之后 mmap 的也要锁);
- **预触页**:锁页≠触页,每个页都要摸一遍才真正装入物理内存——栈、堆、大数组逐页 `memset`/读一遍;
- `transparent_hugepage=never`:THP 后台整理是 µs~ms 级尖峰源;
- swap off;`MAP_POPULATE` 用于大块共享内存。

### 2.4 代码模式与陷阱

```cpp
// 启动期:把一切分配做完
state_buf_.reserve(MAX_N); connection_pool_.warm_up();

// RT 循环内:只碰启动期准备好的东西
// ❌ std::string msg = "err " + std::to_string(code);   // 分配!
// ❌ catch(...) 后做重逻辑                                // 异常展开无界
// ❌ spdlog::info(...)                                   // 内部锁+可能分配
// ✅ err_ring_.push({code, axis, now_ns()});             // 预分配环形,盖旧的
```

**隐形分配黑名单**(最常翻车):`std::string` 拼接、iostream、`shared_ptr` 复制(原子计数+可能分配)、lambda 捕获按值的大对象、`std::function` 装 capture、容器 resize 超容量、`snprintf` 到栈外。**守则:RT 路径只调用你能一眼看出"不分配"的函数;拿不准 = 违禁。**

### 2.5 验收

- RT 路径代码 review 专项:搜索所有调用,逐个确认无分配;
- 长压内存曲线(RSS)恒定——增长即泄漏或分配;
- `mlockall` 返回值检查(失败=没锁上,静默继续=裸奔)。

### 2.6 我们栈的落点

RT 循环禁令清单(linux_rt_guide §2.2);ErrEvent 环形槽(错误记录零分配的设计);遥测环形缓冲 + 非 RT 线程 drain。

## 支柱 3 · 通信原语(线程间怎么说话)

### 3.1 需求

线程间每次数据交换:**无锁(lock-free)、无阻塞(等价于 wait-free 的使用模式)、有界时间**;每条通道语义明确(**最新值**、**队列**、**事件**——三种语义不可混用);慢消费者绝不反压快生产者。

### 3.2 理论基础:为什么锁在 RT 里是死刑

- 互斥锁在竞争时走 futex 进入内核:持有者被抢占/优先级反转 → 等锁时间 = 不可知;
- **优先级反转**:低优先级持锁、高优先级等锁、中优先级抢 CPU → 反转时间无上界(火星探路者号 1997 的经典事故);
- 无锁结构把"互斥"改成"单写者 + 原子发布":写者永不阻塞读者,读者永不阻塞写者——**冲突在结构上不存在**,而非被管理。

内存序(ARM 上是生死线,x86 上是潜伏的假安全):

```
release(store):  先写数据,后翻牌子 —— 牌子可见时数据必完整
acquire(load):   先看牌子,后读数据 —— 看到新牌子必读到新数据
relaxed:         只保原子,不保顺序 —— 仅用于独立计数器
seq_cst:         全序保证 —— 本模式不需要,不用(白付代价)
```

### 3.3 三种通道语义(选错 = 设计错误)

| 语义 | 结构 | 适合 | 不适合 |
|---|---|---|---|
| **最新值(latest)** | 双/三缓冲 + 原子 seq | 状态快照、命令(控制只要 freshest) | 需要全流的场景 |
| **队列(queue)** | SPSC 环形 | 命令序列、事件(不可丢)、日志(可丢) | 控制(积压=延迟无界) |
| **事件(event)** | 原子旗/计数 | 急停、模式切换 | 高频数据 |

**选型口诀**:控制状态用 latest,事务用 queue,警报用 event。混用(比如用队列传状态)会把"取最新"降级成"排队等旧货"。

### 3.4 代码模式:SpLatest(我们的参考实现)

```cpp
template <typename T>   // T: trivially_copyable,无指针
class SpLatest {
	struct alignas(64) Slot { T data; };          // 槽位独占缓存行
	Slot buf_[2];
	uint32_t w_ = 0;                              // 写侧私有
	alignas(64) std::atomic<uint32_t> seq_{0};    // 牌子独占缓存行
	alignas(64) std::atomic<uint32_t> retries_{0};
public:
	bool ready() const { return seq_.load(std::memory_order_acquire) != 0; }
	void publish(const T& v) {
		const uint32_t s = ++w_;                       // 递增(xor 翻转在双拍回绕时 recheck 失灵)
		buf_[s & 1].data = v;
		seq_.store(s, std::memory_order_release);      // 先数据后牌子
	}
	T take() {
		uint32_t s = seq_.load(std::memory_order_acquire);
		T out = buf_[s & 1].data;
		for (;;) {
			uint32_t s2 = seq_.load(std::memory_order_acquire);
			if (s2 == s) return out;
			++retries_; s = s2; out = buf_[s & 1].data; // recheck:写方换槽了,取更新侧
		}
	}
};
```

**多读者规则**:读者只读 → 天然多读者安全(MESI Shared 态,无乒乓);**各读者的"最新"互相独立**(需要多消费者基于同一版本协作 = 版本化快照/RCU 的领域);慢读者(拷贝 ≥ 一拍)会追不上 → 加复制者线程扇出,不直接碰 RT buffer。

### 3.5 失败形态

- 伪共享:两个方向挤同一缓存行,每拍互踢 → 偶发毛刺(`alignas(64)` 防;`perf c2c` 查);
- xor 翻转索引:读方拿住超一拍,recheck 失灵 → 撕裂数据;
- 忘 recheck:读到被写方覆写一半的槽;
- 用 mutex 传高频数据:优先级反转 + 内核仲裁延迟。

### 3.6 验收

- 一致性压测:T 内嵌序号+checksum,双线程 N 小时,每个 take 的 checksum 必须等于某次 publish(**撕裂检测**);**必须在 ARM(Orin)上跑**——x86 过了只说明运气;
- retry 计数长期为 0(挂验收线);
- `perf c2c` 查无伪共享。

### 3.7 我们栈的落点

SpLatest 完整类(linux_rt_guide §2.5.2,含九个设计决策 D1~D9 与四条不变量);SimControlHardware SPSC 命令队列;方向分离(状态/命令两实例)。

## 支柱 4 · 时间与打戳纪律(时间的单一真相)

### 4.1 需求

- **单一时钟源**:整个 RT 域一个 CLOCK_MONOTONIC;仿真域用 ROS time;跨域不换算,数据带 ts 走;
- **打戳在诞生处**:传感器采样时刻 > 主站收帧时刻 > CM 读取时刻——**永远取最早的可用近似**;在转发处打戳 = 把自己的延迟洗白进数据;
- 每个消费者能**自证年龄**(seq/ts 随行);
- 跨源对齐:多源各自打戳 + 偏移标定 + 偏斜常驻遥测。

### 4.2 为什么这是支柱而不是细节

一次打戳错位 = 无中生有的相位误差(直接进延迟账);跨源偏斜(IMU 与关节差 2~3ms)= 状态估计里查三周的"神秘噪声"。**时间戳错的数据比没有数据更危险——它看起来能用。**

### 4.3 Linux 机制

- `CLOCK_MONOTONIC`(不受 NTP 跳变;`CLOCK_REALTIME` 永不进 RT 路径);
- `clock_nanosleep(TIMER_ABSTIME)`(绝对睡眠:不吃 slack、误差不累积);
- `SO_TIMESTAMPNS`/`SO_TIMESTAMPING`:内核/硬件收帧时间戳(SocketCAN 主站的 ts 来源);
- **EC DC**:分布式时钟,从站采样级对齐——物理层白拿的采样级时间戳;
- `/dev/cpu_dma_latency` 持有(深睡退出延迟会污染所有时间测量)。

### 4.4 失败形态

- 用收到数据的时间当采样时间(把总线+软件延迟藏进数据,延迟档案失真);
- 相对睡眠(`sleep_for`)被 timer slack 周期性合并 → "固定 50µs 增量"的神秘抖动;
- 跨源未标定:速度估计莫名噪声。

### 4.5 验收

- 延迟档案逐跳可测可复核(每跳 ts 有来源标注);
- 跨源偏斜遥测 < 阈值(如 200µs)常驻;
- 时钟域换算只发生在明确的边界函数里(grep 可查)。

### 4.6 我们栈的落点

快照 per-source `{seq, ts, alive}`;EC DC 采样级戳(后端文档 §4);CAN 收帧戳 + 抖动进延迟档案;时钟抽象(steady/DC/sim)。

## 支柱 5 · 数据流结构(层的划分)

### 5.1 需求

- **速率分离**:不同频率的工作不同线程(1kHz 环、50Hz 诊断、事件驱动慢通道),节拍之间关系显式(级联或解耦);
- **目标流与闭环分离**:发目标的层(无稳定性风险)与闭环层(受分离律约束)显式分开——CSP/MIT 之别;
- **边界上只有数据契约**:层间传 versioned 快照,不传对象引用、不共享可变状态、不回调;
- **常量延迟与抖动分列**(延迟账的两大列)——因为它们的待遇天差地别。

### 5.2 理论基础:两条定理

**定理一(常量延迟可补偿)**:闭环里纯延迟 τ 的相位损失 360·f·τ,可用一步预测(发 t+τ 的目标)从分子里减掉——**声明清楚即可救**。

**定理二(抖动不可补偿)**:随机 τ 无法预测前推,等效为相位噪声,直接从预算角里扣。**结论:架构设计里"常量换抖动"永远是赚的**——敲门级联把 0~1 拍的随机 tick 变成恒定 1 拍,力控带宽翻倍,就是这个定理的应用。

### 5.3 数据流结构模式

```
非RT 域(家务核)                    RT 域(控制进程,RT核)
  规划/策略/日志/UI                   ┌ CM 循环(目标流或闭环)┐
      │ ingress:校验→ts→SpLatest  →  │                      │
      │                              │  read→update→write   │
      │ ◀— egress:复制者→环形缓冲 ── │                      │
      │ (慢消费者永不碰 RT buffer)    └──────────┬───────────┘
                                              ▼ 主站线程(SpLatest)
                                            驱动器(自带看门狗=安全终点)
```

**分域三铁律**:每条边界有 seq/ts 与单一写者;RT 侧接口无锁无阻塞;校验在 ingress 过境时做(不可信命令在门口拦,不在使用处查)。

### 5.4 失败形态

- 快慢工作同线程:诊断一卡,控制环跟着卡(速率未分离);
- 层间共享可变对象:某个"顺手优化"直接改共享结构 → 撕裂+乒乓(支柱 3 全部白做);
- RT 安全依赖非RT在场(如靠 UI 心跳维持使能)→ UI 卡顿 = 机器停(域间依赖倒置);
- "先都塞 RT 域以后再分" → 漂移方向永远是 RT 域越长越脏。

### 5.5 验收

- 每条边界:契约有版本、有 seq/ts、有年龄遥测;
- 分域图与代码一致(进程/线程清单可审计,准入清单无"临时"成员);
- 杀非RT 域,RT 域行为 = 设计的降级路径(故障注入)。

### 5.6 我们栈的落点

分域规约七步(设计文档 §7);形态 B 双线程与级联;`RobotStateSnapshot/JointCmd` 契约类型(框架 core,版本化);协议层形态盲对象模型。

## 支柱 6 · 故障与降级(出事时的有界行为)

### 6.1 需求

- 每个故障模式有**预先设计**的响应(不是事到临头再想);
- **看门狗链无死角**:每个生产者被它的消费者监视,整链无漏;
- 降级路径与点火序一样是**固定流程**(脚本化,非现场即兴);
- **故障注入可测**——没测过的故障处理等于没写。

### 6.2 覆盖性检查表(方法论核心)

对链上每个生产者问三个问题:

```
1. 谁监视它?(必须存在明确的监视者)
2. 监视者发现它死了之后,第一动作是什么?(必须在 1~2 拍内、无需调度依赖)
3. 死者的恢复路径是什么?(必须有终点:安全态,而不是未定义)
```

本项目答案:非RT ← CM 盯(超时 hold+OTG);CM ← 线程1 盯(cmd_ex 陈旧→急停);CiA402 ← 线程1 盯(ctrl_ex 陈旧→急停);线程1 ← 链路 watchdog + 驱动器看门狗兜底。**无漏。**

### 6.3 设计原则

- **故障响应分两级语义**:"让系统停"(急停旗,直查直发,不经任何中间层)与"让系统知道"(遥测/事件,允许慢)——两者永远分开实现;
- **恢复是重建不是续跑**:INIT 重走 → 重锚定(cmd:=state)→ 才重新放行——原地续跑 = 从错误状态继续累积错误;
- **降级矩阵显式列出**(谁死了系统进什么态),不留在头脑里。

### 6.4 验收(全部故障注入)

| 注入 | 期望 |
|---|---|
| 拔总线 | ≤1 拍急停;恢复后重走 INIT;重锚定后才放行 |
| 杀非RT 域 | RT hold+受控停;重启非RT 后可恢复 |
| 杀 CM | 线程1 检出 cmd 陈旧 → 急停 |
| 杀单从站 | 组语义:全组急停;恢复后全组重走 |

### 6.5 我们栈的落点

双源急停旗(链路层+电机层);两级恢复阶梯;四步点火;两后端文档的故障注入表。

## 支柱 7 · 测量闭环(没有测量就没有实时)

### 7.1 需求

- **常驻遥测**(不是调试时才加):延迟/抖动/overrun/队列水位/错误计数,每秒汇总;
- **装机基线存档**(cyclictest、延迟账逐跳),后续所有测量与之对比;
- **时序回归进 CI**:功能没改但时序劣化 = 失败(和单元测试同级);
- **可归因**:不止知道"慢了 30µs",要知道慢在哪一层(调度?中断?缓存?硬件?)。

### 7.2 工具矩阵

| 工具 | 层 | 归因能力 |
|---|---|---|
| 应用层 seq/ts 遥测 | 应用 | 数据年龄、周期 overrun |
| cyclictest | 内核调度 | 基线;同核对照分流"平台 vs 自身" |
| rtla timerlat/osnoise(≥5.17) | 内核 | **分解**:调度/中断/硬件谁造成 |
| perf c2c | 数据 | 伪共享定位(行+线程) |
| trace-cmd/ftrace | 函数级 | irqsoff/preemptoff 个案深挖 |
| 外部总线测量(示波器/DC 偏移) | 金标准 | 全链末端真值(剥 DC 补偿量化) |

### 7.3 验收线(与 control_course/后端文档一致)

CM 周期 p99 < 周期 10% · 命令年龄 p99 < 5ms · 总线抖动 p99 < 周期 10% · recheck 计数恒 0 · cyclictest max < 周期 10%。

### 7.4 我们栈的落点

周期遥测(min/max/avg)、错误面测绘、延迟档案(`bandwidth_ceiling_hz` 交付字段)、**待办:时序回归进 CI(七支柱中唯一概念已定、机制未落的一项)**。

## 附 B · 两个学科对照(与控制理论课的接缝)

| | 控制理论 | 实时软件架构 |
|---|---|---|
| 对抗谁 | 物理对象:惯性、共振、延迟 | OS/硬件的非确定性:调度、缺页、中断 |
| 核心定律 | 带宽分离律、相位裕度 | Liu-Layland 调度界、有界时间 |
| 核心公式 | 相位 = 360·f·τ(吃裕度) | 同一公式(吃延迟账)+ Σ利用率 ≤ 69% |
| 失败形状 | 振荡、发散 | 卡顿、超时、级联超期 |
| 价值观 | 跟得多准 | 最坏情况多稳 |
| 验证 | 阶跃响应、Bode | cyclictest、时序回归 |

**接缝**:控制工程师给带宽需求(f_max 分子)→ 总线开发者用延迟账答 τ 预算(分母)→ 七支柱保证 τ 不超账 → 回路成立。课程与工作在此合流。

1. 节拍:周期和截止期是多少?利用率多少?和谁同核?

## 附 D · 其他实时系统怎么处理七支柱(光谱与两条 Linux 路线)

### D.1 确定性-生态光谱(五档)

```
确定性 ↑                                              生态/功能 ↑
├────────┬──────────┬───────────┬──────────────┬──────────────┤
│ 裸机    │ RTOS(MCU) │ Xenomai    │ PREEMPT_RT   │ 原生 Linux    │
│ 超循环  │ FreeRTOS  │ 双内核     │ 单内核实时补丁 │ (本项目底座)  │
│ +中断   │ Zephyr    │ Linux旁挂  │ (6.12 主线)   │              │
│         │ RT-Thread │            │              │              │
│ 最坏延迟│ 1~10µs    │ 5~20µs     │ ~50µs 级     │ ms 级(不可用) │
│ 生态    │ 自己写一切 │ Linux 全保留│ Linux 全保留 │ 无限          │
```

一台机器人同时住满整条光谱:从站固件在最左档(MCU 裸机/FreeRTOS),主控 SoC 在右三档。**七支柱是学科要求,不是 Linux 特性——换 RTOS,支柱一条不减,变的只是机制提供者**(左档免费的东西——确定性、无缺页——是右档用全套治理手册换来的;PREEMPT_RT 的本质 = 用"单内核生态"换"与真 RTOS 差一档的确定性",再用七支柱纪律把差额手工补回)。

### D.2 两条 Linux 路线之争:Xenomai 双内核 vs PREEMPT_RT 单内核

**先修框**:不是全称"更好"——延迟地板维度 Xenomai 仍占优(µs 级 vs 几十 µs 级);但 2026 年工程维度行业已实质收敛到 PREEMPT_RT。

| 维度 | Xenomai 双内核 | PREEMPT_RT 单内核 |
|---|---|---|
| 思路 | 把 RT 任务**藏进**cobalt 小内核隔离保护,整个 Linux 被降级为一个空闲任务 | **改造整个大内核**为 RT 安全(自旋锁→可睡眠锁、中断线程化) |
| 延迟地板 | µs 级 ✅ | 几十 µs 级(6.12+ 已进决策不敏感区:1kHz 验收线 max<100µs 已达标) |
| **驱动** | 必须特化(RTnet/analogy),**生态劈两半**;普通驱动一碰穿过 Linux 非实时路径即作废 | **一切驱动自动 RT 安全,零成本** |
| 工具 | RT 域观测受限(ftrace/perf/BPF 大多失效) | 全套 Linux 观测武器照常(= 支柱 7 实力) |
| 维护 | 社区树外项目,cobalt 追内核,维护者个位数 | **6.12 起主线**,发行版官方包,永续 |
| 厂商支持 | 社区自发 | NVIDIA Jetson 官方 RT 包、TI、Intel ECI |
| 适用哲学 | 小而硬的专用系统;硬地板需求(最坏<20µs)/旧内核/RTnet 遗产 | 通用机器人、生态密集型(本项目四要素全占) |

**哲学一句话**:Xenomai 是"修一道墙把 RT 保护起来";PREEMPT_RT 是"把整座城市的法规改造成 RT 安全"——墙内确实更安静,但城里的人(ROS、驱动、工具、下一代工程师)全都要走城门。

### D.3 协处理器/AMP 模式(把 Linux 踢出关键路径)

总线主站跑独立芯片/保留核(裸机或 RTOS),Linux 经共享内存/RPMsg 低频交换目标。对支柱的影响是革命性的:支柱 1/2 的全部 Linux 治理**直接消失**(关键路径上没有 Linux);延迟账"Linux 抖动"整列删除。代价:多一颗芯片、IPC 链自身的新延迟账、双端部署调试。现实注脚:宇树等厂商的电机控制板即此形态——主站矩阵"vendor SDK 后端"的对面就是它。

### D.4 决策规则(升级顺序 = 架构内榨干 → 内核层 → 硬件层,生态税逐档倍增)

```
1kHz 位置控制(CSP)          → PREEMPT_RT + 七支柱(现路线,绰绰有余)
力控/MIT 预算被尾部吃掉      → 先级联敲门(架构内榨干)→ rtla 归因确认尾部来自内核
                              → 才升 Xenomai(很多"内核尾部"实为支柱2/4违规)
带宽 >50Hz 且量产定型        → 协处理器/AMP
从站固件                     → 裸机/FreeRTOS/Zephyr/RT-Thread
```

### D.5 可移植性清单(契约式边界的回报)

SpLatest/快照契约(**原样**,纯 C++17+原子 OS 无关)、延迟账方法论(**原样**)、master.hpp 骨架与协议层(帧层 API 换,骨架原样)、七支柱纪律(**一条不减**)——**唯机制层(IgH/SocketCAN/优先级 API)绑死 Linux,且被契约层隔离**。明天主站搬进 RTOS 芯片,资产转移率接近 100%。
