# rt_tune — RT 线程调优参数化应用

单头文件组件 (`rt_tune.hpp`): 供控制器在**自己的 RT 线程内**调用——亲和性与调度策略只能作用于调用线程自身, 不能跨线程设置。

```cpp
#include "rt_tune.hpp"
// 线程入口处:
unistackbot_common::rt_tune::apply(cpu, fifo_prio, nice_val, name);
```

| 参数 | 语义 |
|---|---|
| `cpu` | -1 = 不绑定; ≥0 = 绑定指定核 |
| `fifo_prio` | 0 = 不动调度策略; >0 = SCHED_FIFO (需 root/CAP_SYS_NICE, 失败降级 SCHED_OTHER 并 WARN) |
| `nice_val` | SCHED_OTHER 下的 nice (仅 fifo_prio=0 时应用) |
| `name` | 线程名 (prctl, top/gdb 可见; nullptr = 不设) |

返回值: 0 = 全部成功; 按位错误码 (`kAffinityFailed`/`kFifoFailed`/`kNiceFailed`)。失败不抛不崩——调优是性能优化, 不是正确性前提。

**分工边界**: 控制器管理器主线程的调优经预留 yaml 参数接口由我们设置 (`thread_priority`/`cpu_affinity`/`lock_memory` —— 参数名是 ros2_control 暴露的接口, 值是我们定的); `rt_tune` 只管自建线程 (如 CM worker、总线主站线程)。

## 测试/基准: bench_rt_tune.cpp

双线程钉核1/核2 (FIFO80) 周期唤醒, 自统计唤醒延迟 (min/avg/p50/p99/max + 超 10/50/100µs 计数); 断言 `rt_tune::apply` 绑核+FIFO 双成功, 失败退出码 1。

```bash
cd unistackbot_common/rt_tune
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic bench_rt_tune.cpp -o /tmp/bench_rt_tune -pthread
/tmp/bench_rt_tune <period_us> <duration_s> [prio=80]   # 如 1000 120
```

参考数据 (2026-09-20, **RT-clean 版**, lowlatency 内核 + isolcpus 全套 + 禁深睡 + performance, 无负载, 120s/档; 详见 `test/results/rt_baseline_isolcpus.md` E 节):

| 档位 | cpu1 p99/max | cpu2 p99/max | >50µs 拍数 |
|---|---|---|---|
| 500Hz | 10.6 / 53µs | 9.9 / 47µs | 1 / 0 |
| 1kHz | 10.0 / 78µs | 8.7 / 42µs | 1 / 0 |

RT 纪律修正记录 (2026-09-20): 初版在测量线程内 `push_back` (realloc 伪影) 且无栈/堆预热与 warmup——修正后 2kHz 档尾部从 ~180µs 降至 ~30µs, 48 万拍零次 >50µs, 此前部分"单发尾部"实为测量工具自身分配伪影。p99 不受影响 (伪影只污染尾部)。

### bench_dual_pump.cpp — 双泵同居核2 场景 (2026-09-24, 设计文档 §17.4 的实测)

双臂 = 双总线段 = 双泵线程**同核同居** (FIFO 90 同优先级) 的调度验证: 泵周期 500Hz、
每拍 7 个均匀分发点 (T/7 时隙), 每分发点 ppoll 睡到期限 → 量迟滞 → 工作突发
(write 20B 非阻塞管道+排干读+~31µs 计算)。三相对比: solo / 双泵错相 T/2 / 双泵同相。

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic bench_dual_pump.cpp -o /tmp/bench_dual_pump -pthread
/tmp/bench_dual_pump 10          # 每相 10s; 默认 prio=90 cpu=2
```

参考数据 (2026-09-24, performance governor, rt_tune_boot 未跑——绝对尾部值注意口径,
相对对比不受影响; 每线程 35000 样本, 突发均值 30.9µs):

| 相 | p50 | p99 | max | >50µs |
|---|---|---|---|---|
| solo 基线 | 1.4 | 4.4 | 12.5 | 0 |
| 双泵错相 T/2 (运行点) | 1.8 | **4.2** | 12.6~33.6 | 0 |
| 双泵同相 (对抗最坏) | — | **37.9** | **56.0** | 4+2 |

结论: ①错相运行点 p99 与 solo 无差别——sleep 主导自然交错论断成立; ②同相最坏迟滞
≈ 恰好一个对方突发 (31µs)——"最坏推迟≈对方一个突发"论断成立; ③全部样本 >100µs=0,
距 285µs 时隙余量 5 倍——**双泵同居核2 设计实测通过**。

**附带真发现 (2026-09-24, 初版 bench 的过期基准意外模拟了积压追赶)**: SCHED_FIFO
**同优先级线程不时间片轮转**——一个不阻塞的线程让同核兄弟完全饿死。泵线程任何
积压追赶场景 (起步错拍/中途停顿) 若"补发过期期限"= 无睡眠狂奔 = 饿死兄弟。
**纪律: 落后超一个时隙即跳到未来期限 (跳帧计数入遥测), 绝不补发**——bench 已内置
该纪律 (跳帧=0 是健康签名), 生产泵实现同款。

**phase4 优先级阶梯 (2026-09-24 用户裁决: EC95 > CAN90 > 串口85 > CM80, 同总线同优先级)**:
模拟三总线同核 (EC: 1kHz/单分发/突发~152µs 假设值; CAN: 1kHz/~80µs; 串口: 现役 500Hz×7 时隙)——
EC95 p99=6.1µs (最高优先级被干净保护, 阶梯生效); CAN90 p50=155µs (每拍排 EC 突发后,
其容迟特性吃得住); **S85 p99=236/max=305µs 被链式抢占 (EC152+CAN80=232µs) 击穿 285µs 时隙**——
"加核/分核触发清单"的第一份数字依据。口径: EC/CAN 突发为假设值 (EC 后端落地实测替换);
串口时隙被击穿的物理后果=晚发 (间隙更大, 无碰撞风险) + 追帧跳过纪律兜底 = 优雅降级非链路损坏。
低优先级最坏延迟的公式由此修正: 不是"对方一个突发", 是"更高优先级突发链之和"。

**phase5 真实最坏部署 (2026-09-24 用户定案: 单核最多 2 总线; 更多总线实例双方案并存
——①首选上核1 与 CM 同住(阶梯优先级天然高于 CM80, CM 核占用 ~1% 被抢占代价≈0)
②加隔离核仍是正当备选; 按届时实例数与实测数据选)**:
EC95+S85 两总线同核 (最大突发 × 最低优先级) —— EC p99=5.7µs 干净; **S85 p99=156.7µs
= EC 突发值 (152µs, 低优先级尾部=高优先级突发链公式兑现), 时隙 285µs 内成立**;
>100µs 占 10.7% 与 EC 占空比 15% 吻合 (常态代价非异常)。max=500µs 为单发离群
(本 boot 未跑 rt_tune_boot, 深睡退出嫌疑, 历史基线有 89-500µs 单发尾部案底;
追帧跳过纪律接住: behind>时隙 → 跳帧+1)。

**phase6 四线程全布局 (2026-09-24, "第三条总线上核1"完整验证)**: 核1 = CM80(500Hz,~24µs)
+ S85a(85,7时隙,对抗同相); 核2 = EC95 + S85b(phase5 复验); 自由相位不跨核同步——
**CM80 p50=33.9/p99=38/max=45.3µs = 恰好一个泵突发(30.9µs), 2ms 周期占用 2.3%, 余量 44×**
(对抗同相=理论上界, 自由相位只会更好); S85a p99=2.5 / EC95 p99=3.3 干净;
S85b p99=155.6(=EC 突发, 公式兑现)/max=207.7(phase5 的 500µs 离群未复现, 支持
"单发系统噪声"判读)。**方案①(总线上核1与CM同住)实测通过**; 全局最坏账: 命令链任一跳
最坏推迟 ≈ 155µs(核2泵)+45µs(CM) ≈ 200µs 量级, 全在预算内 (时隙 285µs / CM 2ms)。

**phase7 全系统单核 (2026-09-24, 核稀缺平台最小配置)**: EC95+S85a+S85b+CM80 四线程同核
(总占用~38%) —— EC p99=5.3/max=13µs (极限配置下仍被保护); 双泵 p99=158/max=192µs
(**干扰链 EC152+同级泵31=183µs 理论值兑现**, <285µs 时隙); CM p99=97/max=126µs
(2ms 周期占用 6.3%)。**全系统一个隔离核 = 核稀缺部署的定案数据点**: 隔离的作用是把
RT 与家务隔离, RT 线程互相之间靠优先级阶梯+突发链预算——隔离核数量按账最小化
(1-2 个), 与机器大小无关; 大机器也不该开 4 个。
