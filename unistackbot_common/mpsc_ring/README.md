# MpscRing · 多写单读覆盖式无锁环

> 组件库第三个原语, **已实现并全测试通过**。家族分工: **SpLatest = 最新 1 个; SpscRing = SPSC 逐条必达; MpscRing = 多写单读, 满则丢旧保新**。
> 立项触发: ulog 日志组件 (多写单读的第一个真实消费场景)。
> 典型场景: **实时日志缓冲** (生产者绝不能阻塞, 旧日志可丢) / **传感器滑动窗口** (只关心最近 N 个样本) /
> **音视频环形缓冲** (允许丢帧, 写者持续覆盖最旧帧)。
> 多工程复用: 零依赖 header-only (仅 C++17 标准库), 整文件夹拷贝即用。

## 1. 为什么市面没有现成的 (设计依据)

| 路线 | 丢旧保新 | RT 可用 | 结论 |
|---|---|---|---|
| 定容数组环 (Vyukov/DPDK/kfifo) | ✗ 满则拒 | ✓ | 数组环快在"读写槽位天然分离"——丢旧使满时读写撞进**同一槽**, 必须补 CAS 逐出 + 消费自检 |
| 无界链表 (Michael-Scott 系) | ✓ 摘头即弃 | ✗ | 链表丢旧容易(摘头节点), 但热路径分配 + 内存回收(hazard/epoch)是 RT 禁区 |
| **本组件** | ✓ | ✓ | 逐出 CAS + 每槽 seq 自检合体的**空缺填补**; 通用库保持中立拒新(容器不销毁数据), 丢旧是应用语义 → 做成语义组件 |

## 2. 契约

- **拓扑**: 多写者(数量任意) / 单读者; 读写均**无阻塞**, push **恒成功**
- **溢出**: 满则逐出最旧未消费条目 —— 最新 N 条**恒完整可达**; 被逐出条目以消费侧"跳号"可观测
- **顺序**: FIFO (同生产者严格保序; 跨生产者按占用位置序)
- **元素**: 可平凡拷贝、不含指针 (`static_assert`); 容量 2 的幂 (`static_assert`)
- **无分配**: 构造时一次定容, 此后零 malloc; 游标/槽 seq 全部 64 位单调 (回绕 ~数百年, 无需保护)
- **自援不弃单**: push 的最坏情况 = 逐出全环旧记录的确定性 CAS 序列 (≤N 次, 微秒级) ——
  **消费者死亡也不挂死业务线程** (生产者靠逐出自援推进); 无 deadline、无弃单
  (弃单会留下无法跨越的 seq 缺口卡死消费者, 两轮评审均否决该方案)

## 3. 状态与不变量

```cpp
std::atomic<uint64_t> tail_;   // 占位游标: 生产者 FAA 抢位 (多写者)
std::atomic<uint64_t> head_;   // 消费游标: 消费者推进 + 生产者逐出, 全走 CAS (双写者!)
struct Cell { std::atomic<uint64_t> seq; T value; };
std::array<Cell, N> cells_;    // 每槽序号仲裁槽状态 (Vyukov 每槽 seq)
```

**槽 seq 编码** (槽 c 在代 g ≡ c (mod N) 上, 2g/2g+1 两态):

| seq 值 | 含义 |
|---|---|
| 2g | 空, 可写 (初始 seq = 2c; 上一代通过者标记产生) |
| 2g + 1 | 已发布, 待消费 |
| 2(g+N) | 通过位置 g 的赢家标记 —— 即下一代的"空" |

不变量: `tail_ - head_ ≤ N`; 序号 64 位单调 (编码 ×2 后回绕仍 ~1.4 亿年 @1kHz, 无需保护)。

## 4. 算法 (实现实况, 与 mpsc_ring.hpp 逐行对应)

seq 编码 **2g / 2g+1** (空 / 已发布); 通过位置 hh 后赢家标记 **2(hh+N)** (下一代空)。
乘 2 的理由: N=1 时 g+1 == g+N, 三态坍缩同值 → 状态机错乱 (压测抓出, 已修)。

```cpp
push(v):                                        // 恒成功, 最坏 ≤N 次 CAS
    pos  = tail_.fetch_add(1, relaxed)          // 占位: FAA, 多生产者互斥
    cell = cells_[pos % N]
    while (cell.seq.load(acquire) != 2*pos)     // 等本槽空 (上一代通过者的标记)
        hh = head_.load(acquire)
        if (pos - hh < N):                      // 环未满: 槽只是没轮到释放 → 不必逐出
            cpu_relax(); continue               //   (评审优化: 免无谓 head CAS 竞争)
        if (cells_[hh%N].seq.load(acquire) == 2*hh+1)      // 真满 → 只逐"已发布"
            if (head_.CAS(hh→hh+1)):
                cells_[hh%N].seq.store(2*(hh+N), release)  // 赢家释放槽
                evicted++
        else cpu_relax()                        // head 上在途写入 → 有界稍候
    cell.value = v                              // 本代唯一写者
    cell.seq.store(2*pos + 1, release)          // 发布

pop(out):
    h = head_.load(acquire); s1 = cell.seq.load(acquire)
    if (s1 != 2*h + 1) return false             // 空 / head 上在途写入 (前缀语义)
    out = cell.value                            // 拷贝 (见下方读契约)
    signal_fence(seq_cst); thread_fence(acquire)  // 双层屏障: 编译器 + 硬件 (见读契约)
    if (cell.seq.load(acquire) != s1) continue  // seqlock 自检: 槽已换代 → 弃条重试
    if (head_.CAS(h→h+1)):
        cell.seq.store(2*(h+N), release)        // 释放槽 (与逐出标记同值, 两路径收敛)
        return true
    retry                                       // 逐出者抢先 → 从最新 head 重试
```

### 消费读契约 (UB 已消除)

载荷存储为**原子字节数组** (`std::atomic<uint8_t>[sizeof(T)]`), 逐字节 relaxed 存取 ——
"消费者读"与"逐出后重写"的交叠从 UB 变为**定义良好的竞争** (单字节原子永不撕裂),
混合的新旧内容由 seq 双验证照旧兜底丢弃。pop 先读局部缓冲、校验通过才落地,
契约 "false 时 out 保持原值" 严格成立。

代价实测: push 逐字节 store 替代 memcpy (+~50ns @128B, 周期预算 0.005%, 无感);
pop 侧 seq_cst 全屏障 (mfence/dmb ish, ~20ns, 后端非 RT 线程)。
x86 relaxed 字节原子 = 普通 mov, ARM = strb/ldrb 零额外指令。
**TSAN 验证通过 (零竞争报告)** —— 改动前该模式必然报 data race, 这是消除的工具级确认。

**读侧屏障 = seq_cst 全屏障 (第六轮评审裁定)**: 校验需要**双向**约束 ——
① 字节 load 不得下移到二次 seq 检查之后 (acquire fence 单向, 不保证此方向);
② 二次 seq 检查不得上移到字节 load 之前 (release fence 单向, 不保证 —— 评审方案二的对称洞)。
x86 上 loads 天然不互重排、ARM `dmb ishld` 恰好双向 load 序 —— 此前靠硬件运气安全,
现改为标准保证。C++ 无 load-load 单向序的 fence 原语, seq_cst 全屏障是唯一正确表达。

演进史: v1 = memcpy + 双层屏障 (内核 seqlock 惯例, 显式接受 UB) → 评审指出 UB 无法被
测试掩盖 → 重新算账发现原"3-8 倍损耗"评估失真 (拷贝微基准倍数 ≠ 场景代价, 绝对值 +50ns
在全部已知场景无感) → 直接消除, 不留双路径 → 第六轮补上屏障方向性 (seq_cst)。

### 评审修复记录 (外部评审四轮, 全部兑现)

| 评审发现 | 轮次/裁定 | 修复 |
|---|---|---|
| head 算术判槽释放 → 消费者标空前生产者写入被覆盖 | 一轮 ✅ 真缺陷 | 生产者改等 `seq==2*pos`, seq 是唯一状态权威 |
| pos<head 无符号下溢死循环 | 一轮 ✅ 真缺陷 | 逐出只过已发布记录 → 未发布占位永不被越过 → pos≥head 恒成立, 无弃单 |
| 拷贝与重写交叠 (严格模型 UB) | 一轮 ⚠️ 结构性代价 | seqlock 双验证 —— 显式接受的偏离 |
| 槽双写者 | 一轮 ✅ 上述后果 | 随协议修复一并消除 |
| N=1 三态坍缩 | 压测发现 ✅ | seq 编码 2g/2g+1 |
| 迟到生产者卡住 head (协作式假设) | 四轮 ✅ 设计限制 | 文档化为边界 (§6): 非死锁是延迟放大, 自愈; 弃单方案两轮评审均否 |
| fence 不阻先前 load 后移 | 四轮 ⚠️ gray area | 双层屏障 (signal_fence + thread_fence), 零成本 belt-and-braces |
| size() 观测下溢 | 四轮 ✅ 真瑕疵 | `t < h ? 0 : t-h` |
| 未满时无谓逐出竞争 | 四轮 ✅ 优化 | 逐出前"不满快速路径" |
| acquire fence 不拦先前 load 下移 (ARM 撕裂外泄路径) | 六轮 ✅ 真缺陷 | pop 读侧屏障改 seq_cst 全屏障 (双向); 评审方案二 release fence 有"二次检查上移"对称洞, 不采纳 |

### 正确性要点

1. 槽唯一写者: 占位 FAA 唯一 + seq 门 (等 2*pos 才写)
2. 逐出与消费互斥: 同一 head CAS, 原子 RMW 无丢更新
3. 撕裂不可外泄: pop 拷贝后验 seq, 槽换代即弃条重试
4. 无死锁: 占位者恒 pos≥head; head 暂阻只来自在途 memcpy (其写者不等待任何人)
5. 无缺口: 不弃单 → 每个占位必发布 → 消费者永无永久缺口

## 5. 性能画像

| 项 | 量级 |
|---|---|
| push | CAS tail 一次 (+满时逐出 CAS 一次), wait-free 意义上的有界步数; ~百 ns |
| pop | 验 seq + 拷贝 + CAS; ~百 ns; 逐出风暴下可能重试 (有界) |
| 吞吐 | 多生产者 CAS 竞争随线程数退化 (MPMC 家族共性); 1kHz×几线程的日志场景余量数个量级 |

## 6. 边界与已知取舍

| 边界 | 说明 |
|---|---|
| **UB 已消除** (第五轮评审触发, 重新算账后裁决) | 载荷改原子字节存储: 读写交叠 = 定义良好竞争, 混合内容由 seq 双验证兜底。原"3-8 倍损耗"评估失真 (微基准倍数≠场景代价), 绝对代价 +50ns 全场景无感 → 直接消除不留双路径。TSAN 零竞争确认 |
| **ARM 验证清单** (挂账, 板卡到手即执行) | ① AArch64 交叉编译同一 test 套件 (QEMU/TCG 无效——内存序近似顺序一致, 测不出弱序重排, 必须真硬件); ② 指标: bad(撕裂流出)=0 恒红线, tears/重试非零属正常; ③ TSAN 在 ARM 复跑 (x86 已零竞争, ARM 同样应为零——载荷已是 atomic 访问); ④ 观察屏障生成的 `dmb` (objdump 确认) |
| **协作式生产者假设** (第四轮评审确认) | 占位后长时间未发布的生产者 (OS 挂起/页错误) 会暂时卡住 head → 其他生产者等待。**非死锁是延迟放大** (写者恢复即自愈; memcpy 窗口纳秒级)。约束: 调用方在 push 前后不应夹长阻塞操作; 与 JCTools/Vyukov"连续前缀"家族属性一致 |
| push 最坏情况 | 满 + 消费者死亡 → 逐出自援全环 (确定性 ≤N 次 CAS, 微秒级); RT 线程常态日志仍不推荐 |
| 消费者非空即失败 | 丢旧语义的读契约: 失败 ≠ 空, 可能是"拷贝被逐出" (调用方循环重试即拿到下一条) |
| 跳号即丢日志 | 逐出的无声性靠消费侧跳号对账兜底 (ulog 汇总) |
| 不持久化 | 逐出即消失 —— "绝对不丢"请落盘/落网 |
| 非自旋等待 | 需要"等空位"的消费者用 OS 队列; 本组件全接口无阻塞 |

## 7. 测试方案 (规范 42 门槛)

1. **功能**: 空 / 填满逐出 / 最新 N 条 FIFO / 容量 1 (SpLatest 退化形)
2. **并发逐出风暴**: 4 生产者 × 各 250 万条 (总 **10M**, 容量 16 → ~72% 被逐出, 逐出路径
   打 ~720 万次), 消费者断言 **每生产者严格单调、全局去重、零撕裂** (自校验负载),
   **账目守恒** received + evicted + remain == pushed; 实测 ~2s/轮, 吞吐 ~500 万条/s
3. **消费者停摆自援**: 消费者故意停摆 → 生产者靠逐出自援**持续 push 不挂死** (计时断言业务线程
   脱身时间有界); 消费者恢复后从新 head 继续 (跳号对账)
4. **多核 + 目标平台**: x86_64 + ARM (弱序架构上 fence/CAS 的正确性才算验完)
