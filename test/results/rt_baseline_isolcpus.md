## ⚠️ 翻案: "500ms = RT throttling 实锤" 归因撤销 (2026-09-20 下午复核)

第三轮 sysctl 已被重启还原为默认 950000, 500ms 事件**不复现** — 前一轮 "-1 后消失" 是相关不因果。机制账三重反证:

1. **SCHED_OTHER 不进 RT 带宽账本**: `sched_rt_runtime_us` 只限 per-CPU FIFO/RR 任务的累计运行时间; `cpu_load.py` 是裸 SCHED_OTHER 自旋 (`python -c 'while True: pass'`), 时间不计预算 → 负载档与无负载档在预算消耗上无差别, 解释不了第一轮"只有负载档中招"的模式。
2. **占空比差两个数量级**: 触发 throttle 需 1s 窗口内 RT 累计 950ms (95% 占空比); cyclictest 1kHz 每拍 µs 级 (<1%), CM 链 500Hz × WCET ~11µs (≈0.6%) — 没有任何任务凑得出。
3. **数值对不上 throttle signature**: 真被 throttle 时本周期已跑满 950ms, 距 1s 周期边界最多剩 50ms, 惩罚应为几十 ms 级随机残留; 实测四格全 500.0ms±0.04ms, 是确定的半秒定时行为特征, 不是调度配额特征。

第一轮 500ms 事件本身真实 (四格全中), 真凶未定; 隔离全套 (含 irqaffinity + managed_irq) 后不复现, 与中断/负载路径相关性强 — 隔离已在事实上消除该类事件。

## 裁决: `sched_rt_runtime_us` 保持默认 950000, **不持久化 -1**

- 本机 RT 占空比 << 阈值, throttle 永不触发 (上账), 调它没有收益。
- 950ms 默认值是同核 RT 线程疯转时 (如未来 worker bug 死循环) 的**保险丝**: 冻 ≤50ms 后恢复。
- -1 则保险丝拔掉: RT 疯转无限饿死 ksoftirqd/watchdog, 更难恢复。
- 前基线文档"建议写 /etc/sysctl.d/90-unistackbot-rt.conf" **撤回**。

**无负载 (首轮含 4kHz, 留档)**:

| 档位 | 核1 Min/Avg/Max (µs) | 核2 Min/Avg/Max (µs) | 拍数/线程 (120s) |
|---|---|---|---|
| 500Hz (i=2000) | 1 / 3 / **42** | 1 / 3 / **43** | 60k |

- **调优有效**: Avg 4→2-3µs; 500Hz Max 89/90 → 42/43µs。**"无负载尾巴=C2 退出"部分实锤**——C2 (127µs 档) 贡献了约一半尾巴 (89-43≈46µs), 剩余 ~40µs 级另有来源 (未定)。
- **Max 随拍数增长**: 178/327µs 尖刺出现在 120k/480k 拍的长窗, 单发偶发, 符合极值分布 (与"30s 短窗低估尾部"同一课); 区分"单发 vs 持续"需直方图阈值计数 (`-h` 已采但未入表)。
- **负载档全绿且优于无负载** (9-12µs vs 21-178µs): 负载使整机/包级电源态恒热 + 隔离核被 IPI 骚扰在浅档, 唤醒路径最短。
- **uncore 锁频对照实验: 假设否决** (2026-09-20 下午追加)。锁 4.8GHz 后无负载三档复测 Max:
  500Hz 152/135µs (锁前 42/43) / 1kHz 23/19 (锁前 21/178) / 2kHz 42/31 (锁前 22/53) —
  六对数字同量级波动, **无可辨识收益**。结论: 残余 20-180µs 尾巴 = 单发偶发事件 (极值分布), 与 uncore/C-state 均无关;
  `rt_tune_boot.sh` 的 uncore 段默认关 (LOCK_UNCORE=0), 当前已锁值重启自动回默认。定位单发源需 ftrace 级追踪, 500Hz 下占 2-8% 预算, **收益不足, 到此为止**。
- **边界 (用户裁定, 2026-09-20)**: 本机是 **lowlatency 内核 (CONFIG_PREEMPT 全抢占), 不是 PREEMPT_RT**——内核仍有不可抢占路径与硬中断上下文, 上表负载数字是实测**不是最坏情况上界**; 真要跑最大负载场景的硬保证, 需切 PREEMPT_RT 内核 (中断/临界区线程化)。当前三档数据支持开发/仿真链, 真机最大负载验收以 RT 内核为准。

- **std::thread 版复测** (同日, 线程从 pthread 改 std::thread 后): p99 8.9-11.2µs 全档一致, 单发尾部同族 (max 20-337µs, >100µs 每档 0-1 次), 组件断言六次全绿 — **线程机制改动功能等价, 数据可延续**。

## F. 场景二: SpLatest 双核链路基准 (2026-09-20 傍晚, `unistackbot_common/sp_latest/bench_sp_latest_chain.cpp`)

布局: 核2 总线线程 FIFO90 (IgH 原生拍内顺序: 拍首 send → 模拟往返 100µs → receive → publish fb → read cmd 供下拍, 执行器一阶模型) / 核1 CM 线程 FIFO80 (update, P 跟踪 1Hz 正弦); 两条 SpLatest 值通道 (Feedback/Command, 32 关节 900B 级报文, 整型定宽, stamp=int64_t ns)。

**终版 = 裸通道 + 原生顺序, 零同步补丁。** 裁决史 (全部试作后否决, 入档防复发):
- 错相半周期 / 总线观测 cmd-miss 移相控制律: **总线 = DC 锚定的节拍源不可移相**, 否决;
- readWait 有界自旋 / seq 等新帧 / 撕裂率监控: **晚一帧不重要** (最坏同相 9.6% miss 下 errRMS 与零 miss 差 2%), 为 1% 概率的 2% 代价上机制是过度设计, 否决。
- 关键结构: 总线拍内原生顺序把通道操作推离拍首 (~往返 100µs), **同时启动 φ=0 恰是安全相位**; 撞窗带只在 φ≈±100µs±2µs 两处窄缝 (500Hz ~0.4% / 1kHz ~0.8% / 2kHz ~1.6%, 启动时一次性掷骰, 同频不漂); 撞上后果 errRMS +2% 无感, 重激活 CM 即重掷。上游死 = seq 冻结 = StaleWatch 域 (安全语义)。
- 回头加等待机制的判据: 实测 errRMS/相位裕度退化 (2kHz+ 力控高带宽场景)。

**终版实测**:

| 轮 | 相位 | 撕裂 fb/cmd | miss | errRMS (rad) | wake p99 (µs) |
|---|---|---|---|---|---|
| 500Hz ×30s | 同相 0 | 0 / 0 | 0 | 0.1599 | 10.1 / 11.6 |
| 1kHz ×30s | 同相 0 | 0 / 0 | 0 | 0.0870 | 9.6 / 10.5 |
| 2kHz ×30s | 同相 0 | 0 / 0 | 0 | 0.0445 | 9.1 / 10.0 |
| 1kHz ×60s | 随机 497µs | 0 / 0 | 0 | 0.0881 | 8.4 / 10.0 |
| 1kHz ×30s (终版+init防护) | 随机 596µs | 0 / 0 | 0 | 0.0878 | 8.5 / 10.3 |
| 2kHz ×30s (终版+init防护) | 随机 **104µs — 真实撞上 +100µs 撞窗带** | 0 / 4 | 15 (0.025%) | 0.0454 (+2%) | 8.4 / 9.7 |

结论: ① 双通道 32 关节交互不伤实时性 (wake p99 ≤12µs 全档, 零超 100µs); ② 同相/随机启动全零撕裂零 miss; ③ e2e 与相位差数学自洽 (fb 年龄 ≈ φ); ④ **2kHz 随机相位真实撞上撞窗带 (104µs)**: miss 0.025%、errRMS +2%、尾窗归零 — "撞上也不疼"从推断变实测。场景二闭环。

补充契约 (同日): init 占位帧识别 — init 初值非实际反馈 (真机总线=占位), 判据 `seq_out == kInitFrameSeq(2)` (组件公开常量), 调用方忽略不进控制; 真机照抄姿势见 bench 两消费点。上一帧语义分工: 组件保证失败不脏写 out, 调用方保证接收变量循环外持久。
